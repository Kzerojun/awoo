## 단위 테스트(Unit Testing)

### 1. **정의**
단위 테스트는 소프트웨어의 가장 작은 단위인 "함수" 또는 "메서드"가 기대한 대로 동작하는지 검증하는 테스트입니다. 일반적으로 개발자가 작성한 코드의 일부가 예상대로 작동하는지 확인하기 위해 수행됩니다.

### 2. **목표**
단위 테스트의 주요 목표는 코드의 각 단위가 독립적으로 정확하게 동작하는지 확인하여, 전체 시스템에서 발생할 수 있는 문제를 미리 방지하는 것입니다.

### 3. **특징**
- **독립성**: 단위 테스트는 각 기능을 독립적으로 테스트하며, 다른 코드의 영향을 받지 않아야 합니다.
- **자동화**: 단위 테스트는 자동으로 실행될 수 있으며, 코드 변경 후 쉽게 다시 실행할 수 있습니다.
- **빠른 피드백**: 코드가 변경될 때마다 즉시 테스트 결과를 확인할 수 있어 빠른 피드백을 받을 수 있습니다.

### 4. **장점**
- **버그 조기 발견**: 코드 작성 초기에 버그를 찾아내어 수정할 수 있습니다.
- **리팩토링 용이**: 기존 코드를 변경하거나 최적화할 때 단위 테스트가 자동으로 결과를 검증해주므로 리팩토링이 안전합니다.
- **문서화**: 테스트 코드는 코드의 동작을 설명하는 역할을 하여, 다른 개발자가 코드를 이해하는 데 도움이 됩니다.

### 5. **도구**
- **JUnit**: Java에서 가장 많이 사용하는 단위 테스트 프레임워크.
- **Mockito**: Java에서 Mock 객체를 생성하여 의존성을 분리한 테스트를 작성할 때 사용되는 라이브러리.
- **TestNG**: JUnit과 유사한 단위 테스트 프레임워크로, 더 강력한 기능을 제공합니다.

### 6. **단위 테스트 작성 시 주의사항**
- **독립성 유지**: 각 테스트는 다른 테스트와 독립적으로 실행되어야 하며, 다른 테스트에 영향을 미치지 않아야 합니다.
- **빠른 실행**: 단위 테스트는 빠르게 실행될 수 있어야 하며, 실행 시간이 너무 길면 자동화 테스트의 효율성이 떨어집니다.
- **명확한 결과**: 각 테스트는 명확한 성공 또는 실패 결과를 제공해야 합니다.

단위 테스트는 코드 품질을 유지하고, 소프트웨어의 유지보수성을 높이는 중요한 개발 기법입니다.
