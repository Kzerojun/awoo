# 📝 트랜잭션 어노테이션 정리

## 1. 트랜잭션(Transaction)이란?  
- 데이터베이스의 논리적 작업 단위로, 여러 개의 작업이 하나의 단위로 실행됨.  
- 트랜잭션이 성공하면 **커밋(Commit)**, 실패하면 **롤백(Rollback)** 수행.  
- **ACID 원칙**(원자성, 일관성, 격리성, 지속성)을 따름.  

---

## 2. `@Transactional` 어노테이션  
Spring에서 **트랜잭션을 관리**하기 위한 어노테이션.  
메서드 또는 클래스 단위에서 선언할 수 있음.  

### 2.1 사용 방법  
```java
import org.springframework.transaction.annotation.Transactional;

@Service
public class SampleService {

    @Transactional
    public void someTransactionalMethod() {
        // 트랜잭션이 적용되는 코드
    }
}

```


## 3. 트랜잭션 속성

### 3.1 `rollbackFor` (롤백 대상 예외 지정)
- 기본적으로 **Unchecked 예외(`RuntimeException`, `Error`)**가 발생하면 롤백됨.
- **Checked 예외(`Exception`)는 기본적으로 롤백되지 않음.**

```java
@Transactional(rollbackFor = Exception.class)
public void someMethod() throws Exception {
    throw new Exception("체크 예외 발생!"); 
    // 기본적으로 롤백되지 않지만 rollbackFor 설정으로 롤백됨.
}

```


### noRollbackFor (롤백 제외 예외 지정)
- 특정 예외가 발생해도 롤백되지 않도록 설정 가능.
```java
@Transactional(noRollbackFor = IllegalArgumentException.class)
public void someMethod() {
    throw new IllegalArgumentException("롤백되지 않음!");
}

```


### 3.3 propagation (전파 옵션)
- 특정 예외가 발생해도 롤백되지 않도록 설정 가능.
```java
@Transactional(propagation = Propagation.REQUIRED) // 기본값
public void someMethod() {
    // 부모 트랜잭션이 있으면 참여, 없으면 새로운 트랜잭션 생성
}

```
- 전파 유형 정리

### 트랜잭션 전파 유형 정리

| 전파 타입         | 설명 |
|------------------|----------------------------------------------|
| `REQUIRED`      | 기존 트랜잭션이 있으면 참여, 없으면 새로 생성 (기본값) |
| `REQUIRES_NEW`  | 기존 트랜잭션 무시하고 새로운 트랜잭션 생성 |
| `MANDATORY`     | 기존 트랜잭션이 있어야 실행, 없으면 예외 발생 |
| `SUPPORTS`      | 트랜잭션이 있으면 참여, 없으면 트랜잭션 없이 실행 |
| `NOT_SUPPORTED` | 트랜잭션 없이 실행 (기존 트랜잭션 일시 중지) |
| `NEVER`        | 트랜잭션 없이 실행 (기존 트랜잭션이 있으면 예외 발생) |
| `NESTED`       | 부모 트랜잭션이 있으면 중첩 트랜잭션 생성 |


## 4. @Transactional 주의사항

- 프록시 기반으로 동작하므로, 같은 클래스 내에서 호출하면 적용되지 않을 수 있음.

- private 메서드에는 적용되지 않음.

- 트랜잭션을 지원하는 **프레임워크(DB, JPA 등)**에서만 동작함.

- Spring Boot에서는 AOP 기반으로 트랜잭션을 관리하므로, @EnableTransactionManagement를 활성화할 필요 없음.
