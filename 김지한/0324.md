# Spring AOP (Aspect-Oriented Programming)

AOP(Aspect-Oriented Programming)는 공통적인 관심사를 분리하여 코드의 중복을 줄이고, 기능을 모듈화하는 프로그래밍 기법입니다. 스프링 AOP는 핵심 비즈니스 로직 외에도 공통적인 기능을 처리하는 데 유용합니다. 예를 들어, 로깅, 트랜잭션 관리, 보안 등을 AOP를 통해 처리할 수 있습니다.

## 1. AOP의 주요 개념

- **Aspect**: 공통적인 관심사를 모듈화한 것. 예를 들어, 로깅, 트랜잭션 관리 등이 AOP에서 하나의 Aspect가 됩니다.
- **Join Point**: AOP에서 Advice가 적용될 수 있는 지점을 말합니다. 보통 메서드 실행 시점이 Join Point가 됩니다.
- **Advice**: 실제로 수행할 작업을 정의하는 부분입니다. 예를 들어, 메서드 실행 전후에 로깅을 추가하는 것 등이 Advice에 해당합니다.
- **Pointcut**: 어느 Join Point에 Advice를 적용할지 결정하는 표현식입니다.
- **Weaving**: Aspect를 실제 객체에 적용하는 과정입니다. AOP는 런타임에 또는 컴파일 타임에 이 과정을 거칩니다.

## 2. 스프링 AOP의 기본 사용

스프링에서 AOP를 사용하려면 `@Aspect` 어노테이션을 사용하여 Aspect를 정의하고, `@Before`, `@After`, `@Around` 등의 어노테이션으로 Advice를 작성합니다.

#### 예시:

1. **Aspect 클래스 정의**

```java
@Aspect
@Component
public class LoggingAspect {

    // 메서드 실행 전에 로그를 출력
    @Before("execution(* com.example.service.*.*(..))")
    public void logBefore(JoinPoint joinPoint) {
        System.out.println("Before method: " + joinPoint.getSignature().getName());
    }

    // 메서드 실행 후에 로그를 출력
    @After("execution(* com.example.service.*.*(..))")
    public void logAfter(JoinPoint joinPoint) {
        System.out.println("After method: " + joinPoint.getSignature().getName());
    }
}
```

2. Advice 종류

- @Before: 메서드 실행 전에 호출

- @After: 메서드 실행 후에 호출

- @Around: 메서드 실행 전후에 호출하며, 메서드 실행을 제어할 수 있음

예시 (메서드 실행 전후 제어):
```java
@Around("execution(* com.example.service.*.*(..))")
public Object aroundMethod(ProceedingJoinPoint joinPoint) throws Throwable {
    System.out.println("Before method: " + joinPoint.getSignature().getName());
    Object result = joinPoint.proceed(); // 실제 메서드 실행
    System.out.println("After method: " + joinPoint.getSignature().getName());
    return result;
}
```

## 3. AOP의 적용 대상

AOP는 주로 다음과 같은 경우에 사용됩니다:

- 로깅: 메서드 호출 시점에 로그를 남기거나, 메서드 실행 결과를 로그에 기록

- 트랜잭션 관리: 메서드 실행 전후로 트랜잭션 시작과 종료를 처리

- 보안: 특정 메서드에 대한 접근을 제어

- 성능 모니터링: 메서드 실행 시간을 측정하여 성능을 모니터링

## 4. 스프링 AOP와 AspectJ
스프링 AOP는 프록시 기반 AOP로, 주로 메서드 실행 전후의 공통 관심사를 처리하는 데 사용됩니다.

AspectJ는 컴파일 타임 또는 로드 타임에 AOP를 적용할 수 있는 강력한 AOP 프레임워크입니다. AspectJ는 스프링 AOP보다 더 다양한 기능을 제공하며, 스프링에서 AspectJ를 사용할 수도 있습니다.

## 5. AOP 설정 방법
Java Config: @EnableAspectJAutoProxy 어노테이션을 사용하여 AOP 기능을 활성화합니다.

예시:
```java
@Configuration
@EnableAspectJAutoProxy
public class AppConfig {
    // AOP 설정을 위한 설정 클래스
}
```

## 요약

- AOP는 공통 관심사를 분리하여 코드의 중복을 줄이고, 유지보수성을 높이는 프로그래밍 기법입니다.

- 스프링 AOP는 @Aspect, @Before, @After, @Around 등의 어노테이션을 사용하여 Aspect와 Advice를 정의합니다.

- AOP는 로깅, 트랜잭션 관리, 보안 등 다양한 분야에 활용될 수 있습니다.
