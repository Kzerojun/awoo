# **DDD (Domain-Driven Design) 정리**

## **1. 개념**
- **DDD (Domain-Driven Design)**는 **소프트웨어의 핵심 로직을 도메인 중심으로 설계**하는 방법론.
- 비즈니스 로직과 복잡한 요구사항을 효과적으로 반영하기 위해 **도메인 모델을 기반으로 개발**.
- 개발자가 도메인 전문가(비즈니스 담당자)와 협력하여 **현실 세계의 문제를 소프트웨어로 해결**하는 것이 목표.

---

## **2. DDD의 핵심 개념**
| 개념                       | 설명 |
|----------------------------|------|
| **도메인 (Domain)**         | 비즈니스가 해결하려는 문제 영역 |
| **도메인 모델 (Domain Model)** | 도메인을 개념적으로 표현한 모델 (클래스, 관계, 동작 등) |
| **엔티티 (Entity)**         | 고유한 식별자를 가지는 객체 (e.g., `User`, `Order`) |
| **밸류 오브젝트 (Value Object, VO)** | 식별자가 없고 속성 값이 동일하면 동일한 객체로 간주 (e.g., `Money`, `Address`) |
| **애그리게이트 (Aggregate)** | 관련된 엔티티와 VO의 묶음 (트랜잭션 단위) |
| **애그리게이트 루트 (Aggregate Root)** | 애그리게이트의 대표 엔티티, 외부에서 직접 접근 가능한 유일한 엔티티 |
| **리포지토리 (Repository)** | 애그리게이트를 저장하고 조회하는 역할 (DB 접근) |
| **도메인 서비스 (Domain Service)** | 특정 엔티티에 속하지 않는 도메인 로직을 처리하는 서비스 |
| **애플리케이션 서비스 (Application Service)** | 도메인 로직을 호출하고 조합하여 유스케이스를 실행 |
| **이벤트 (Event)**          | 도메인에서 발생하는 중요한 변경 사항을 나타냄 |
