# Sprign MVC

## MVC란?

- 디자인 패턴

- 개발 영역을 MVC (Model, View, Controller)로 구분하여 각 역할에 맞게 코드를 작성하는 개발 방식

- UI 영역과 도메인(비즈니스 로직) 영역으로 구분되어 서로에게 영향을 주지 않으면서 개발과 유지보수가 가능

- Model : 데이터

- View : 사용자 인터페이스 요소

- Controller : 데이터와 비지니스 로직사이의 상호 동작 관리

## MVC의 사용 이유

- MVC 사용 목적 : 

    - 포넌트가 서로 분리되어 각자의 역할에 집중할 수 있기 때문에 시스템 결합도를 낮출 수 있다.

    - 유지보수가 쉬움

    - 중복코드를 제거

    - 애플리케이션의 확장성 및 유연성이 증가

## Spring MVC 구조

### DispatcherServlet

- Front Controller의 역할을 수행하며 Request를 각각의 Controller에게 위임

- 클라이언트의 요청을 처리하는 가장 앞 단의 Controller로써 요청부터 응답까지 전반적인 처리 과정을 통제

### HandlerMapping

- 요청을 처리할 컨트롤러를 탐색

- 구체적인 Mapping은 xml파일이나 java config 관련 어노테이션 등을 통해 처리

### HandlerAdapter

- Mapping된 컨트롤러의 실행을 요청

### Controller

- DispatcherServlet이 전달해준 HTTP 요청을 처리하고 결과를 Model에 저장

    - 직접 요청을 처리하며, 처리 결과를 반환

### ModelAndView

- Controller에서 반환된 결과값


### View

- 결과를 보여주는 화면


## Spring MVC 동작 구조

<img src="./image/Spring MVC 동작 구조.png" height="100%" width="100%">

1. 클라이언트가 서버에 요청을 보내면, Front Controller인 DispatcherServlet 클래스가 요청을 받음

2. DispatcherServlet이 요청된 컨트롤러로 Mapping된 컨트롤러가 존재하면 @RequestMapping을 통해 요청을 처리할 메소드로 이동

3. Controller는 요청을 Service로 전달

4. Service는 로직 처리 및 및 DAO와 DB 접근 및 요청 처리 후 데이터 전달달

5. Service는 전달받은 데이터를 컨트롤러에 전달

6. Controller는 객체 요청에 맞는 View 정보를 담아 DispatcherServlet에게 전송

7. DispatcherServlet은  ViewResolver에게 전달받은 View 정보를 전달

8. ViewResolver는 응답할 View에 대한 JSP를 찾아 DispatcherServlet에게 전달

9. DispatcherServlet은 응답할 뷰의 Render를 지시하고 뷰는 로직을 처리

10. DispatcherServlet은 클라이언트에게 Rending된 뷰를 응답하며 요청을 마침
