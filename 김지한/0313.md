# Spring에서 예외 처리(Exception Handling)

## 1. 예외 처리의 필요성
- 예외(Exception)는 프로그램 실행 중 예상치 못한 오류를 의미함.
- 적절한 예외 처리는 사용자 경험을 개선하고, 시스템의 안정성을 높이는 데 도움을 줌.
- Spring에서는 다양한 예외 처리 방법을 제공하여 유지보수성을 향상시킬 수 있음.

## 2. Spring에서 예외 처리 방법

### 2.1 try-catch 블록 사용 (기본 방법)
- 가장 간단한 예외 처리 방식이지만, 코드가 복잡해질 수 있음.
```java
try {
    // 예외 발생 가능 코드
} catch (CustomException e) {
    // 예외 처리 로직
}
```

### 2.2 @ExceptionHandler (개별 컨트롤러 예외 처리)
특정 컨트롤러에서 발생하는 예외를 처리하는 방식.

```java
@RestController
@RequestMapping("/api")
public class ExampleController {

    @GetMapping("/example")
    public String example() {
        if (true) { // 예제 조건
            throw new CustomException("예외 발생!");
        }
        return "Success";
    }

    @ExceptionHandler(CustomException.class)
    public ResponseEntity<String> handleCustomException(CustomException e) {
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(e.getMessage());
    }
}
```


### 2.3 @ControllerAdvice (전역 예외 처리)
여러 컨트롤러에서 발생하는 예외를 일괄 처리하는 방식.
```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(CustomException.class)
    public ResponseEntity<String> handleCustomException(CustomException e) {
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(e.getMessage());
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<String> handleGlobalException(Exception e) {
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body("서버 오류 발생");
    }
}
```


### 2.4 @ResponseStatus (예외 클래스에서 상태 코드 지정)
특정 예외 발생 시 자동으로 HTTP 상태 코드를 반환하도록 설정할 수 있음.
```java
@ResponseStatus(HttpStatus.BAD_REQUEST)
public class CustomException extends RuntimeException {
    public CustomException(String message) {
        super(message);
    }
}

```


## 3. 예외 처리 시 고려할 사항

### 3.1 적절한 HTTP 상태 코드 반환

| 상태 코드 | 의미 |
|-----------|----------------|
| `400 Bad Request` | 클라이언트 입력 오류 |
| `401 Unauthorized` | 인증 실패 |
| `403 Forbidden` | 권한 부족 |
| `404 Not Found` | 리소스 없음 |
| `500 Internal Server Error` | 서버 내부 오류 |


### 3.2 일관된 예외 응답 형식 제공 (JSON)
JSON 형식으로 에러 메시지를 반환하면 API 사용자가 이해하기 쉬움.

```java
public class ErrorResponse {
    private String message;
    private int status;

    public ErrorResponse(String message, int status) {
        this.message = message;
        this.status = status;
    }

    // getter, setter
}

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(CustomException.class)
    public ResponseEntity<ErrorResponse> handleCustomException(CustomException e) {
        ErrorResponse errorResponse = new ErrorResponse(e.getMessage(), HttpStatus.BAD_REQUEST.value());
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(errorResponse);
    }
}

```

## 4. 결론

- 개별 예외 처리는 @ExceptionHandler 사용.

- 전역 예외 처리는 @ControllerAdvice + @ExceptionHandler 사용.

- @ResponseStatus를 활용하여 예외 클래스에서 상태 코드 지정 가능.

- 예외 응답을 일관된 형식(JSON)으로 제공하면 API 유지보수성이 향상됨.
