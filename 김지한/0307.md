# GET과 POST의 차이점 및 사용법 정리

## 1. GET과 POST 개요

### GET 메서드

- 정의 : 데이터를 요청할 때 사용하며, 요청한 데이터를 URL의 쿼리 스트링(Query String)으로 전달함.

- 특징
    - 요청 데이터를 URL에 포함 (?key=value 형식)
    - 브라우저 캐싱 가능 (이전 요청을 재사용할 가능성이 있음)
    - 서버 로그에 기록됨 (보안상 중요한 데이터 노출 위험)
    - 길이 제한 존재 (URL 길이 제한으로 인해 긴 데이터 전송에 부적합)
    - 멱등성(Idempotent) 보장 (같은 요청을 여러 번 보내도 같은 결과 반환)

---

### POST 메서드

- 정의 : 데이터를 생성, 전송할 때 사용하며, 요청 데이터를 HTTP Body에 포함함.

- 특징
    - 요청 데이터를 Body에 포함 (URL에 노출되지 않음)
    - 브라우저 캐싱되지 않음
    - 로그 파일에 기록되지 않음 (보안적으로 GET보다 안전)
    - 데이터 크기 제한이 없음 (파일 업로드, 대량 데이터 전송 가능)
    - 멱등성이 없음 (같은 요청을 여러 번 보내면 다른 결과가 나올 수 있음)

---

## 2. GET vs POST 차이점 정리

| 항목  | GET | POST |
|------|-----------|-----------|
| **데이터 전송 위치** | URL(Query String) | HTTP Body |
| **브라우저 캐싱** | ✅ (기본적으로 캐싱됨) | ❌ (기본적으로 캐싱되지 않음) |
| **서버 로그 기록** | ✅ (URL에 포함) | ❌ (Body는 일반적으로 기록되지 않음) |
| **브라우저 히스토리 저장** | ✅ (뒤로 가기 시 URL 포함) | ❌ (기본적으로 저장되지 않음) |
| **데이터 크기 제한** | ✅ (URL 길이 제한 존재) | ❌ (제한 없음) |
| **보안성** | 낮음 (URL 노출 위험) | 높음 (Body에 포함, URL에 노출되지 않음) |
| **사용 예시** | 검색, 조회 | 로그인, 회원가입, 데이터 수정 |
