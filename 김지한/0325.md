## 동기(Synchronous)와 비동기(Asynchronous)

### 1. **동기(Synchronous)**

- **정의**: 작업이 순차적으로 처리되는 방식으로, 하나의 작업이 끝나야만 다음 작업이 실행됩니다.
- **특징**:
  - 각 작업은 이전 작업이 완료될 때까지 대기합니다.
  - 코드 흐름이 직관적이고 이해하기 쉬운 특징이 있습니다.
  - 대기 시간 동안 다른 작업을 할 수 없어 시간이 많이 소요될 수 있습니다.

### 2. **비동기(Asynchronous)**

- **정의**: 작업을 시작한 후, 그 작업이 끝날 때까지 기다리지 않고 다른 작업을 실행합니다. 작업이 끝나면 결과를 받아옵니다.
- **특징**:
  - 여러 작업을 동시에 처리할 수 있어 전체 처리 시간이 줄어듭니다.
  - 대기 시간 동안 다른 작업을 할 수 있어 시스템 자원의 활용도가 높습니다.
  - 작업 흐름이 복잡할 수 있으며, 결과를 처리하기 위한 추가적인 방법이 필요할 수 있습니다.

### 3. **차이점 요약**

| 특징        | 동기(Synchronous)                                   | 비동기(Asynchronous)                                     |
|-------------|------------------------------------------------------|----------------------------------------------------------|
| **처리 방식**  | 이전 작업이 끝날 때까지 다음 작업이 대기               | 작업이 완료될 때까지 기다리지 않고 다른 작업을 실행       |
| **효율성**    | 순차 처리로 시간이 오래 걸릴 수 있음                   | 병렬 처리로 전체 처리 시간이 단축                        |
| **사용 예시**  | 간단한 작업이나 작은 규모의 시스템에서 유용            | 대규모 시스템, I/O 작업, 네트워크 요청 처리에 유용        |
| **복잡도**    | 코드가 직관적이고 간단                               | 콜백 함수, `Future` 등의 처리가 필요하여 코드 복잡도가 증가 |

### 4. **사용 사례**
- **동기**: 간단한 계산, 파일 읽기/쓰기, 요청-응답 처리 등
- **비동기**: 네트워크 요청, 파일 다운로드, 대규모 데이터 처리 등

비동기는 동기보다 성능과 자원 활용 측면에서 더 유리할 수 있지만, 코드의 복잡도가 증가할 수 있으므로 상황에 맞는 적절한 선택이 필요합니다.
