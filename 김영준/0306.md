## Spectifications란?
JPA를 사용하다 보면 다양한 조건으로 데이터를 조회해야 하는 경우가 많다. 일반적으로 조건마다 개별적인 메서드를 만들어 처리하는데, 비즈니스 로직이 복잡해질수록 메서드가 계속 증가하고 코드의 가독성이 떨어지는 문제가 발생한다.

이를 해결하기 위해 나온 기술이 JPA Specifications이다. Specifications을 활용하면 동적으로 조건을 조합하여 가독성이 좋은 코드로 효율적인 데이터 조회가 가능하다.

 

Spring Jpa가 제공하는 인터페이스, 여기서 T는 JpaEntity를 의미


```
public interface Specification^ extends Serializable { // not, where, and, or 메서드 생략

@Nullable
Predicate toPredicate(Root<T> root,
CriteriaQuery<?> query, CriteriaBuilder cb);

}
실제 조회 조건 클래스 구현
public class OrdererIdSpec implements Specification<OrderSummary> {
    private String ordererId;

    public OrdererIdSpec(String ordererId) { 
        this.ordererId = ordererId;
    }

    @Override
    public Predicate toPredicate(Root<OrderSummary> root, 
                                 CriteriaQuery<?> query, 
                                 CriteriaBuilder cb) {
        return cb.equal(root.get(OrderSummary_.ordererId), ordererId);
    }
}
```
Root<OrderSummary> : OderSummary 테이블을 의미한다.
CriteriaBuilder : 조건을 만들기 위한 도구입니다. equal, and, or 같은 메서드를 제공해요.
CriteriaQuery : 현재 만들고 있는 쿼리자체를 의미.
Criteria API

자바 애플리케이션에서 데이터베이스 쿼리를 동적으로 생성하고 실행하기 위해 JPA(Java Persistence API)에서 제공하는 API
 

이렇게 각각의 스펙의 클래스를 만들지 않고 하나의 클래스에서 메소드로 제공하는 방법도 존재한다.

```
스펙 생성 기능 클래스
public class OrderSummarySpecs {
    
    public static Specification<OrderSummary> ordererId(String ordererId) {
        return (Root<OrderSummary> root, CriteriaQuery<?> query, CriteriaBuilder cb) ->
            cb.equal(root.<String>get("ordererId"), ordererId);
    }

    public static Specification<OrderSummary> orderDateBetween(LocalDateTime from, LocalDateTime to) {
        return (Root<OrderSummary> root, CriteriaQuery<?> query, CriteriaBuilder cb) ->
            cb.between(root.get(OrderSummary_.orderDate), from, to);
    }
}
```

실제 JPA 레포지토리 인터페이스에서는 위의 코드와 같이 사용하면 됩니다.

스펙 조합 (and, or, not 기타등등)
스펙 인터페이스는 default 메소드로 And, Or, Not등을 제공합니다. 위의 실제 코드는 직접 살펴보는걸 추천

사용방법의 아래와 같다.
```
Specification<OrderSummary> spec = OrderSummarySpecs.ordererId("userl") .and(OrderSummarySpecs.orderDateBetween(from, to));
```
