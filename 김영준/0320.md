# Jpa Entity 생성 시 default값 설정하기 with @Dynamic Insert

우리가 Jpa Entity를 생성할 때 기본값을 설정해두려고 하는 상황이 자주 생깁니다.
저는 핀테크 프로젝트를 진행하며 계좌 잔액(BigDecimal) 타입의 기본값을 설정하려는 상황이 생겼습니다.
어떻게 기본값을 설정했는지 알아보고자 합니다.
## JPA Entity 기본값 설정방법
### 1. 빌더 패턴으로 만들시 기본값 설정해두기 - 추천
나는 보통 생성자를 통해 인스턴스를 만드는게 아니라 보통 빌더패턴을 활용해서 인스턴스를 생성합니다.
제일 쉽게 기본값을 생성 할 수 있는 방법은 다음과 같습니다.
```
    @Builder
    public PaymentEntity(String password, Integer memberId) {
        this.password = password;
        this.memberId = memberId;
        this.balance = BigDecimal.ZERO;
    }
```
하지만 단순히 빌더로 끝내지 않고, JPA 자체로 기본값을 설정할 수 있는 방법이 궁금해졌습니다. Jpa로 기본값 설정은 될꺼같은데 하는 방법을 몰라 순수 궁금증으로 자료를 찾아보았습니다. 찾아본 결과는 아래와 같습니다.
### 2. JPA @Dynamic Insert + @ColumnDefalut 사용 - 비추천
@DynamicInsert란 null인 필드를 제외하고 SQL INSERT 쿼리를 생성합니다. 주로 성능 최적화를 위해 사용됩니다.
왜 사용할까요?? 성능 최적화를 최대한 하기 위해 사용합니다.
```
The @DynamicInsert annotation is a powerful feature in Hibernate, but its usage should be applied selectively based on specific scenarios. One such scenario involves entities with many nullable fields. When an entity has fields that may not always be populated, @DynamicInsert optimizes the insert operation by excluding unset columns from the SQL query. This reduces the size of the generated query and improves performance.This annotation is also beneficial when certain database columns have default values. Preventing Hibernate from inserting null values allows the database to handle those fields using its default settings. For example, a created_at column might automatically set the current timestamp when a record is inserted. By excluding this field in the insert statement, Hibernate preserves the database’s logic and prevents overriding default behavior.
 ```
@DynamicInsert를 사용하면 null인 필드를 제외하고 INSERT 쿼리를 생성합니다. 그렇다면 nullable = false로 설정된 컬럼에는 어떻게 값을 입력할 수 있을까요?
이때 @ColumnDefault를 활용하면 가능합니다. @ColumnDefault는 DB 스키마에 기본값을 직접 지정하는 방식이므로, JPA가 null 값을 삽입하지 않도록 하면 DB에서 자동으로 기본값이 설정됩니다.
즉, @DynamicInsert를 적용한 상태에서 엔티티를 저장(save)하면, balance 값이 null일 경우 DB에서 자동으로 0이 할당됩니다.
 
다른 방법으로 @Column의 columnDefinition 속성을 활용해 DB 컬럼 정보를 직접 지정하는 방법도 있습니다. 다만, 이 역시 DB 의존성이 생길 수 있으므로 신중하게 선택해야 합니다.
 
제 생각에는 두번째 방법은 좋지 않는 방법이고 억지로 집어넣으려고 시도해본것처럼 느껴집니다.
궁금해서 방법을 몇가지 찾아봤지만 간단한게 가장 좋은거 같습니다.
