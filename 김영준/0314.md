## 데이터베이스에서 락이란?
데이터베이스를 사용하다 보면 여러사람이 동시에 같은 데이터를 수정하거나 조회하려는 상황이 종종 발생합니다.

이때 데이터의 일관성과 무결성을 지키기 위해 필요한 개념이 바로 락이라고 볼수있습니다.

락은 단어 그대로 데이터를 잠가 놓는 기능으로, 다른 사용자가 잠긴 데이터에 접근하거나 변경 하지 못하도록 제한하는 역할을 합니다.



락은 보통 두가지의 종류로 나눠집니다.

비관적 잠금(Pessimistic Locking)
낙관적 잠금(Optimistic Locking)
자세하게 알아봅시다.

### 비관적 잠금
데이터에 접근할 때 다른 트랜잭션이 동시에 데이터를 수정할 가능성을 미리 걱정하고, 아예 처음부터 락을 걸어 다른 데이터 접근을 차단하는 방법입니다.



특징은 다음과 같습니다.

락을 미리 획득 : 트랜잭션이 데이터를 읽거나 수정하기전에 배타적 락이나 공유 락을 걸어 다른 트랜잭션의 접근을 막습니다.
충돌 방지 : 데이터 충돌이 발생할 것 같은 가능성을 원척적으로 차단합니다.
대기 발생 : 다른 트랜잭션이 락을 해제할 떄까지 기다려야 하므로 처리 시간이 길어질 수 있습니다.
### 낙관적 잠금
데이터 충돌이 자주 일어나지 않을거라 가정하고, 락을 미리걸지 않고 트랜잭션이 끝날때 충돌 여부를 확인하는 방식입니다.



특징은 다음과 같습니다.

락 없음 : 트랜잭션 진행중에는 락을 걸지 않고 자유롭게 데이터를 읽고 수정합니다.
버전 관리 : 데이터에 버전 번호나 타음스탬프를 붙여, 수정하려는 시점에 데이터가 변경되었는지 확인
충돌 감지 : 트랜잭션 커밋시점에 만약 다른 트랜잭션에 의해 변경되었다면 롤백을 시도합니다.
그렇다면 JPA 에서는 어떻게 이 락을 사용할 수 있을까요??

## Transaction Locks in JPA
JPA는 앞서 말한 두가지의 락을 지원합니다.

그렇다면 코드상에서 어떻게 락을 사용할 수 있을까요?? @Lock 어노테이션을 사용하여 락을 설정할 수 있습니다.



@Lock에 필요한 잠금 모드 타입을 전달하면됩니다.

락 종류는 LockModeType이라는 enum값으로 지정하면 됩니다.

@Lock(LockModeType.OPTIMISTIC_FORCE_INCREMENT)
public List<Example> fetchExample();


위의 코드처럼 enum 값을 사용해서 지정하면됩니다.

Lock TimeOut 설정하기
우리가 그렇다면 비관적인 락을 사용한다고 가정해봅시다. 비관적 잠금을 사용할 떄, 데이터베이스가 락을 바로 걸지 못한다면 

LockTimeOutException을 발생시킵니다. 이를 방지하기위해 JPA 에선 락 타임아웃을 설정할 수 있습니다.



바로 @QueryHints 어노테이션을 사용하면됩니다.
```
@Lock(LockModeType.PESSIMISTIC_READ)
@QueryHints({@QueryHint(name = "jakarta.persistence.lock.timeout", value = "3000")}) // 3초 대기
```
여기서는 데이터베이스가 락을 3초 동안 기다린다는 의미입니다.

기본 타임아웃 값은 데이터베이스의 엔진의 설정에 따라 달라집니다.
