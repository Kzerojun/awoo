# MySQL 아키텍처 및 동작 원리와 최적화 기법

저는 조회 기능을 최적화하는 방법에 관심이 생겨 이번 프로젝트에서 개선을 해보기 위해 MYSQl의 기본부터 시작하기로 했습니다. 조회 기능 개선을 위해서는 MySQL이 무엇이며, 어떻게 동작하고 어떤 구조로 이루어져 있는지를 정확히 이해하는 것이 필수적입니다. 이 문서에서는 MySQL의 기본 아키텍처부터 동작 원리, 그리고 최적화 기법까지 차근차근 알아보겠습니다.

---

## MySQL 아키텍처

MySQL의 아키텍처는 다음과 같이 구분됩니다:

### 1. MYSQL 접속 클라이언트
- **역할**:  
  사용자의 응용 프로그램과 소통하는 계층입니다.
- **특징**:  
  프로그래밍 언어를 위한 접속 API를 제공하며, Shell Script를 통해서도 접속이 가능합니다.

### 2. MYSQL 엔진
- **역할**:  
  MySQL의 두뇌 역할을 하며, 클라이언트 접속과 SQL 요청을 처리합니다.

### 3. MYSQL 스토리지 엔진
- **역할**:  
  실제 데이터의 저장, 검색, 수정, 삭제 등 I/O 작업을 수행합니다.
- **특징**:  
  대표적으로 InnoDB와 MyISAM 등 다양한 스토리지 엔진을 플러그인 형태로 지원합니다.

> 자세한 내용은 아래의 **MySQL 동작 순서**에서 다루겠습니다.

---

## MySQL 동작 순서

MySQL의 SQL 처리는 다음과 같은 단계로 진행됩니다:

### 1. Parser
- **문법 검사**:  
  SQL 문이 문법 규칙을 따르는지 확인합니다.
- **구조 분석**:  
  SQL 문을 구성하는 요소를 식별하고, 이를 파스트리라는 내부 데이터 구조로 변환합니다.

### 2. PreProcessor
- **역할**:  
  - Parse Tree를 기반으로 SQL 문장 구조를 체크합니다.
  - Parse Tree의 토큰이 유효한지 검증합니다.

### 3. Optimizer
- **역할**:  
  파싱된 쿼리를 받아 효율적으로 처리할 실행 계획을 수립합니다.
- **최적화 방법**:
  - **비용 기반 최적화**: 각 실행 계획의 비용을 계산하여 가장 비용이 낮은 계획을 선택합니다.
  - **규칙 기반 최적화**: 옵티마이저에 내장된 우선순위에 따라 최적화 작업을 수행합니다.

### 4. Engine Executor
- **역할**:  
  옵티마이저가 만든 실행 계획대로 스토리지 엔진을 호출하여 레코드를 읽고 씁니다.

### 5. Storage Engine
- **역할**:  
  SQL 쿼리의 요청에 따라 데이터를 저장, 검색, 수정, 삭제하는 I/O 작업을 수행합니다.

## MySQL의 핵심 Storage Engine

### InnoDB
InnoDB는 데이터베이스의 신뢰성과 성능을 보장하기 위한 다양한 기능을 제공합니다.

- **PK에 의한 클러스터링**  
  - 기본 키(PK)를 기준으로 클러스터링 인덱스를 사용하여 데이터를 정렬해 물리적으로 저장합니다.  
  - 이로 인해 PK를 이용한 범위 검색이나 단일 레코드 조회 속도가 향상됩니다.  
  - 단, 쓰기 작업 시 인덱스 재구성이 발생할 수 있어 쓰기 성능이 다소 저하될 수 있습니다.

- **클러스터링 인덱스**  
  - 데이터를 저장할 때 기준이 되는 정렬된 순서를 제공합니다.

- **MVCC (Multi Version Concurrency Control)**  
  - Commit과 RollBack 기능을 기본으로 제공하여, 동시성 제어를 지원합니다.

- **InnoDB 버퍼풀**  
  - 디스크에 저장되기 전 데이터를 임시로 버퍼링하는 공간입니다.

- **언두 로그**  
  - 변경되기 이전의 데이터를 백업해두는 공간으로, 데이터의 이전 버전으로 복구할 때 사용됩니다.

- **격리수준에 따른 동작**  
  - **READ_UNCOMMITTED**: 아직 커밋되지 않은 변경 사항도 보이므로, 버퍼풀의 최신 데이터를 그대로 반환합니다.
  - **READ_COMMITTED, REPEATABLE_READ, SERIALIZABLE**:  
    커밋되지 않은 변경 사항은 보이지 않아야 하므로, 데이터 페이지에서 변경된 데이터를 읽은 후 언두 로그를 참조해 해당 레코드의 과거 버전을 재구성합니다.

- **레코드 단위 잠금**  
  - **Shared Lock**: 읽기 작업을 허용하며, 여러 트랜잭션이 동시에 같은 행을 읽을 수 있습니다.
  - **Exclusive Lock**: 쓰기 작업 시 사용되며, 다른 트랜잭션이 해당 행에 접근하지 못하도록 차단합니다.

### MyISAM
MyISAM은 간단한 구조와 빠른 읽기 성능을 제공하지만, 다음과 같은 제한이 있습니다:

- **특징**:
  - **클러스터링 지원**: 지원하지 않음
  - **트랜잭션 지원**: 지원하지 않음
  - **외래키 지원**: 지원하지 않음
  - **테이블 단위 잠금**: 사용
  - **키 캐시 사용**: 인덱스 정보만 버퍼링
  - **전문 검색 및 공간 좌표 검색**: 지원

MyISAM은 이러한 특성 때문에 트랜잭션 처리나 고급 잠금 기능이 필요한 경우에는 적합하지 않습니다.
