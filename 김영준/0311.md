# JPA는 왜 기본 생성자가 필요한가?

JPA는 리플렉션(Reflection)을 사용하여 엔티티 객체를 생성합니다. 이 과정에서 매개변수가 없는 기본 생성자가 반드시 필요합니다.

## 리플렉션이란?
구체적인 클래스 타입을 알지 못해도, 그 클래스의 메소드, 타입, 변수들에게 접근할 수 있도록 해주는 API입니다.

컴파일된 바이트 코드를 통해 Runtime에 동적으로 특정 Class의 정보를 추출할 수 있습니다.
```
@Getter
class Person {
    private String name;
    private int age;

    public Person() {
        this.name = "Unknown";
        this.age = 0;
    }

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public void sayHello() {
        System.out.println("Hello, my name is " + name + " and I am " + age + " years old.");
    }
}
public class Main {
    public static void main(String[] agrs) {
        Object person = new Person();
        person.getName() // 이 코드를 사용 할 수 없다.
    }
}
```
지금 상황과 같이 person은 구체적은 클래스 타입을 알지 못하기 때문에 getName()이라는 함수를 사용할 수 없습니다.

이런 상황을 해결할 수 있는 기능이 Reflection 입니다.
```
public class Main {
    public static void main(String[] args) throws NoSuchMethodException, InvocationTargetException, IllegalAccessException {
        Object person = new Person();

        // JAVA Reflection
        Class<?> c = Person.class; // 제네릭 타입 지정
        Method getName = c.getMethod("getName"); // getName 메서드 가져오기
        String name = (String) getName.invoke(person); // 메서드 호출 (매개변수 없음)

        System.out.println("name = " + name);
    }
}
```
위 코드에서 보듯이, 리플렉션은 클래스 타입을 알지 못하더라도 메서드나 필드에 동적으로 접근할 수 있도록 도와줍니다. JPA 역시 리플렉션을 사용해 엔티티 객체를 생성하고 필드에 값을 설정합니다. 여기서 중요한 점은, 리플렉션으로 객체를 생성하려면 기본 생성자가 필수라는 것입니다.

기본 생성자의 접근 지시자가 public or protected만 되는이유
이유는 Proxy 객체에 연관이 있습니다.

Proxy객체는 엔티티를 조회할때 지연 로딩을 사용하기 위해 만들어집니다.

 

지연로딩을 한다면 원본 엔티티를 상속한 Proxy 객체가 반환됩니다.

이떄 Proxy객체는 원본 엔티티를 상속하기 때문에 접근지시자가 private이면 에러를 발생합니다.
```
추가 정보
@NoArgsConstructor(access = AccessLevel.PROTECTED)
```
우리는 기본생성자를 사용해서 엔티티를 생성하지 않기에, protected로 선언하여 외부 패키지에서 접근하지 못하도록 제한할 수 있습니다. -> JPA 엔티티의 무분별한 생성을 방지할 수 있습니다.

 

### 지연 로딩
지연 로딩은 JPA에서 필요할 때만 데이터를 가져오는 방식입니다.

예를 들어, A라는 엔티티는 B라는 엔티티를 포함하고 있습니다.

A의 엔티티를 데이터베이스에서 가져올 때 지연로딩 이라는 B가 당장 필요하지 않다면 데이터베이스에서 가져오지 않고, 빈 껍데기(프록시)만 만들어둡니다. 즉, B를 쓸 준비만 합니다.

B를 진짜로 사용할때 그때 데이터 베이스에서 정보를 가져옵니다.

### 즉시 로딩
즉시 로딩은 지연로딩과 다르게 당장 필요하지 않더라도 모든 연관된 정보를 가져오는 방식입니다.

위의 상황과 같이 A의 엔티티를 데이터베이스에서 가져올 때 연관된 B의 정보 모두를 데이터베이스 에서 가져옵니다.

B를 사용할때, A에서 이미 가져왔기 때문에 쿼리를 두번 날리지 않아도 됩니다.
