

## Gateway란?
Gateway는 라우팅 및 프로토콜 변환을 담당하며 마이크로 서비스의 중개자 역할을 담당합니다. 이를 통해 서비스는 클라이언트와 독립적으로 확장이 가능하며 보안, 모니터링을 위한 단일 지점을 제공합니다.

왜 Gateway가 필요할까요?? 우리 하나의 상황을 상상해봅시다. 마이크로 서비스의 서버서 3개정도만 있다 가정해봅시다. 이렇다면 클라이언트에서 직접적으로 각각의 요청을 보내도 무리가 되지않을껍니다. 하지만 10개? 20개? 라면?? 이걸 클라이언트 측에서 처리하기엔 무리가 있습니다. 이러한 문제점을 해결하기 위해 개발된 Gateway패턴입니다.

 


 

### Gateway 구성요소
Gateway는 요청이 오면 정의된 설정에 따라 요청을 라우팅하고 사전에 설정된 필터들을 작동시킵니다. 설정은 Route 단위로 구성이 되며 Route는 다시 Predicate와 Filter로 구성됩니다. Predicate는 요청을 구분할 때 사용하는 값인데, Path, Method, Host 등으로 요청을 매칭하고 Filter는 매칭된 요청에 대한 전처리나 서비스의 응답에 대한 후처리를 구현합니다.

 


저희 프로젝트는 Spring Cloud Gateway를 구성하여 사용하고있습니다. Spring Cloud Gateway는 webflux를 통해 구현되어 있으며 설정하는 방법은 두가지 방법이 존재합니다.

1. Java DSL
2. application.yml 설정파일에서 설정
저는 applicatino.yml파일로 설정하고자 합니다.

### Spring Cloud Gateway
기본 사용방법은 다음과 같습니다. 우선 의존성을 추가.
```
ext {
    set('springCloudVersion', "2024.0.0")
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'

    // Spring Cloud Gateway 추가
    implementation 'org.springframework.cloud:spring-cloud-starter-gateway'
}

dependencyManagement {
    imports {
        // Spring Cloud Gateway 추가
        mavenBom "org.springframework.cloud:spring-cloud-dependencies:${springCloudVersion}"
    }
}
 ```

그 이후 application.yml 파일을 이용하여 라우팅을 설정해주면 됩니다.
```
  cloud:
    gateway:
      routes:
        - id: member-service
          uri:
          predicates:
            - name: Path
              args:
                patterns: /
            - name: Method
              args:
                methods:
                  - POST

                  ```
id : 라우팅 규칙의 고유 식별자
uri : 요청이 라우팅될 대상 URL, predicates의 조건에 부합하면 라우팅됩니다.
predicates : 요청이 라우팅 규칙에 매핑되는지 판단하는 조건 조건이 모두 참이어야 라우팅
name : Path - 요청의 경로가 특정패턴과 일치하는지
args : pattersns : 경로 매핑, / : 루트
name : Method : HTTP 메서드를 기준으로 요청을 필터링
