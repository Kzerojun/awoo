# B+ Tree와 B-Tree 개요

B+ tree는 단순한 이진 탐색 트리(binary search tree)와 달리, 대용량 데이터를 디스크에 효율적으로 저장하고 빠른 검색 속도를 제공하는 데 최적화된 구조입니다. 실제로 MySQL의 InnoDB 스토리지 엔진은 이 B+ tree를 기반으로 **클러스터링 인덱스(Clustered Index)** 를 구성하여, 데이터가 정렬된 상태로 저장되고 검색 시 성능을 극대화할 수 있도록 돕습니다.

---

## B-Tree

B-트리는 이진 트리를 일반화한 형태로, 각 노드가 최대 N개의 자식 노드를 가질 수 있도록 확장된 **균형 잡힌 트리** 입니다. 이를 통해 데이터의 삽입, 삭제, 검색을 효율적으로 수행할 수 있습니다. 단순히 자식 노드의 수를 늘리는 것뿐만 아니라, 자식 노드와 **키(key)** 를 어떤 기준으로 저장할지에 대한 규칙이 필요하며, 이 규칙은 B-트리의 **차수(Order)** 인 M을 기준으로 정의됩니다.

**Balanced Tree**  
모든 리프 노드들이 같은 레벨에 위치하기 때문에 조회 성능은 로그 시간(즉, **O(log N)**)으로 일정합니다.

### B-트리의 주요 파라미터

- **M**: 각 노드가 가질 수 있는 최대 자식 노드 수  
  _예: M차 B-트리_
- **M-1**: 각 노드가 가질 수 있는 최대 키(key) 수  
  _키는 자식 노드 사이의 경계를 구분하는 역할을 합니다._
- **⌈M/2⌉**: 각 노드가 유지해야 하는 최소 자식 노드 수  
  _단, 루트 노드와 리프 노드는 예외 처리될 수 있습니다._
- **⌈M/2⌉ - 1**: 각 노드가 유지해야 하는 최소 키(key) 수  
  _루트 노드를 제외한 모든 노드에 적용됩니다._

### B-트리의 규칙

- 내부 노드의 키 수가 **x개**라면, 자녀 노드의 수는 항상 **x+1개**입니다.
- 각 노드는 최소 한 개의 키를 가져야 하므로, internal 노드는 최소 **두 개의 자녀**를 가져야 합니다.
- **키는 오름차순**으로 정렬됩니다.
- 모든 **리프 노드**들은 같은 레벨에 위치합니다.

---

## B+ Tree

B+ 트리는 모든 데이터가 **리프 노드**에 저장되는 균형 잡힌 트리입니다. 내부 노드는 오직 인덱스로만 사용되며, 리프 노드들은 연결 리스트로 서로 연결되어 있습니다.

- **범위 쿼리**와 **순차적 데이터 접근**이 매우 빠릅니다.
- 루트 노드는 값의 범위를 나타냅니다.
- **B-Tree와의 차이점**: 데이터는 전부 리프 노드에 저장되고, 내부 노드는 인덱스로만 사용됩니다.
