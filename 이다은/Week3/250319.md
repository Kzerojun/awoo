### 📅 2025.03.19 (수) - Next.js의 App 라우팅

Next.js 13부터 도입된 **App Router**는 기존 Pages Router와는 구조와 개념이 다르다. 폴더 기반의 라우팅은 유지되지만, 더 유연한 컴포넌트 기반 설계가 가능해졌다.

#### 📁 App Router 기본 구조

`/app` 디렉토리 내 폴더와 파일명이 곧 URL 경로가 된다.

```
/app
  /home
    page.tsx     → /home
  /product
    /[id]
      page.tsx   → /product/:id
  layout.tsx     → 공통 레이아웃
  page.tsx       → 루트 페이지 (/)
```

#### 🚀 주요 개념

- `page.tsx`: 실제 렌더링되는 페이지 컴포넌트
- `layout.tsx`: 해당 폴더 이하에 공통으로 적용되는 레이아웃
- `loading.tsx`: 서버 컴포넌트 로딩 중 표시할 UI
- `error.tsx`: 해당 페이지에서 발생한 에러 처리 컴포넌트
- `@types`, `interface.ts`: 폴더별로 타입을 관리하면 유지보수가 쉬움

#### 🧩 예시 코드: 간단한 라우팅

```tsx
// app/home/page.tsx
export default function HomePage() {
  return <div>홈 화면</div>;
}
```

#### ✅ 실무 팁

- **폴더 단위로 도메인 분리**: `app/product`, `app/account` 등 도메인 기반으로 구조화
- **공통 UI는 layout.tsx에 정의**: 예: 사이드바, 헤더, 인증 체크 등
- **조건부 렌더링은 클라이언트 컴포넌트에서 처리**: `use client` 명시
