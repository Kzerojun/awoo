### 📅 2025.03.21 (금) - 기본 에디터 (`vi`, `nano` 등)와 병합 시 발생하는 문제

Git에서 `commit`, `merge`, `rebase` 등을 실행할 때 기본 에디터가 실행될 수 있다.  
특히 병합(merge) 시 자동으로 `vi`가 열리는 경우가 많은데, 이를 모르고 있으면 당황할 수 있다.

#### 🔹 기본 에디터 종류

| 에디터    | 특징                                   |
| --------- | -------------------------------------- |
| `vi`      | 기본 탑재, 단축키 기반 (진입장벽 높음) |
| `nano`    | 직관적인 UI, 기본 제공 (터미널 친화적) |
| `vim`     | `vi` 확장판, 더 강력한 기능 제공       |
| `code`    | VSCode 에디터 실행 (`code --wait`)     |
| `notepad` | Windows 기본 메모장 사용 가능          |

#### 🔥 병합(Merge) 시 `vi`가 실행되는 이유

- Git은 병합 커밋 메시지를 자동으로 입력하지 않고, 사용자가 확인 후 작성하도록 기본 설정됨
- 별도로 에디터 설정을 하지 않았다면 `vi`가 기본값으로 실행됨

#### 🛠️ 해결 방법

1. **기본 에디터 변경 (nano로 설정)**

   ```bash
   git config --global core.editor "nano"
   ```

   이후부터는 `nano`가 열려서 좀 더 직관적인 UI로 편집 가능.

2. **병합 시 커밋 메시지를 바로 입력**

   ```bash
   git merge branch-name -m "Merge branch-name into main"
   ```

   - `-m` 옵션을 사용하면 에디터 없이 즉시 병합 완료.

3. **VSCode를 기본 에디터로 설정**
   ```bash
   git config --global core.editor "code --wait"
   ```
   - 병합 시 VSCode가 실행되며, 변경 사항을 확인 후 저장하면 자동으로 종료됨.

#### ✅ 실무 팁

- `vi`를 빠져나오려면 `ESC` → `:wq` → `Enter` 입력
- `nano`에서 저장하려면 `CTRL + X` → `Y` → `Enter`
- 협업 시 팀 내에서 공통된 에디터를 설정하는 것이 좋음

> **기본 에디터를 바꾸면 병합할 때 더 편해진다. `vi`가 어렵다면 `nano`나 VSCode를 설정해볼수도 있다.**
