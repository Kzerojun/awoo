### 📘 주요 TypeScript 개념 정리

#### 1. 배열 타입 명시와 useState

```ts
const [checkedList, setCheckedList] = useState<boolean[]>(Array(9).fill(false));
```

**왜 이렇게 했는가?**

- TypeScript는 `useState`에서 초기값만 보고 타입을 추론하는데,  
  `Array(9).fill(false)`만 넣으면 `any[]`로 추론됨 → `checkedList[index]` 접근 시 타입 오류 발생

**원리**

- 배열의 요소 타입을 명시적으로 지정해주면 `.map`, `.every`, `.filter` 등 고차 함수 사용 시 타입 안정성이 보장됨

---

#### 2. 상태 업데이트 시 불변성(immutability) 유지

```ts
const updated = [...checkedList];
updated[index] = !updated[index];
setCheckedList(updated);
```

**왜 이렇게 했는가?**

- React는 참조가 바뀌어야 렌더링을 다시 수행함
- 기존 배열을 직접 수정하는 것은 리액트에서 감지되지 않음 (`checkedList[index] = true` ❌)

**실무에서의 중요성**

- Redux나 Zustand 등 상태 관리 라이브러리에서도 이 불변성은 핵심 원칙이므로 숙지 필요

---

#### 3. `.every(Boolean)` 패턴 활용

```ts
const allChecked = checkedList.every(Boolean);
```

**왜 이렇게 했는가?**

- 간결하게 “모든 항목이 true인지” 확인할 수 있음

**원리**

- `.every(fn)`은 모든 요소가 `fn(element)`를 만족할 때만 `true` 반환
- `Boolean`은 값이 truthy인지 검사하는 함수 → `Boolean(true) → true`, `Boolean(false) → false`

---

### ✨ 느낀 점

- `boolean[]`로 체크 상태를 관리하면 index 기반 처리라 처음에는 구조가 단순하지만,
  데이터가 많아질수록 key-value 구조로 바꾸는 게 좋을 수도 있다는 점을 느꼈다
- 특히 `.every(Boolean)`과 같은 함수형 패턴은 코드가 깔끔하고, 조건문이 길어지지 않아 유지보수가 쉬워짐
