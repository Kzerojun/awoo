## 💡 JavaScript 심화 - 스코프, 클로저, this

### ✅ 스코프 (Scope)

> 스코프는 **변수에 접근할 수 있는 범위**를 의미한다.

| 타입        | 설명                                                     |
| ----------- | -------------------------------------------------------- |
| 전역 스코프 | 함수 외부에서 선언된 변수는 어디서든 접근 가능           |
| 함수 스코프 | `var`로 선언된 변수는 함수 내부에서만 유효               |
| 블록 스코프 | `let`, `const`로 선언된 변수는 `{}` 블록 내부에서만 유효 |

- JS는 기본적으로 **렉시컬 스코프(Lexical Scope)** 를 따른다 → 선언된 위치가 기준
- **TDZ (Temporal Dead Zone)**  
  선언 전에 변수에 접근할 수 없는 구간  
  ex) `console.log(x)` → `let x = 10` 이전에 접근하면 ReferenceError

- **호이스팅(Hoisting)**  
  `var`, `function` 선언은 스코프 최상단으로 끌어올려진다.  
  단, `let`, `const`는 호이스팅은 되지만 TDZ로 인해 초기화 전 접근 불가

### ✅ 클로저 (Closure)

> 클로저는 **함수가 외부 스코프의 변수를 참조**하는 구조

- 클로저의 조건
  1. 함수 내부에 함수가 존재
  2. 내부 함수가 외부 함수의 변수를 참조

```js
function outer() {
  const name = "TIL";
  return function inner() {
    console.log(name);
  };
}
const fn = outer();
fn(); // TIL
```

- 클로저는 외부 함수가 종료되어도 `name`을 참조할 수 있음 → 메모리 유지
- **용도**

  - 프라이빗 변수처럼 사용 가능
  - 모듈화, 정보 은닉
  - 이벤트 핸들러, setTimeout, setInterval 내부에서 자주 등장

- 면접 팁
  - 클로저 남용 시 **메모리 누수** 발생 가능성
  - `GC(Garbage Collector)`가 수거하지 못하는 케이스 질문 자주 나옴

### ✅ this

> this는 **함수를 호출하는 방식**에 따라 값이 결정되는 특별한 키워드

| 호출 방법          | this 값                                                |
| ------------------ | ------------------------------------------------------ |
| 일반 함수 호출     | 브라우저에서는 `window`, strict 모드에서는 `undefined` |
| 객체의 메서드 호출 | 메서드를 호출한 객체                                   |
| 생성자 호출        | 새로 만들어진 인스턴스                                 |
| 화살표 함수        | 상위 스코프의 this (렉시컬 this)                       |

- 화살표 함수 특징
  - 자체적인 this를 만들지 않고 외부 스코프의 this를 그대로 사용
  - 이벤트 리스너나 콜백 함수에서 유용하게 사용됨

```js
const obj = {
  name: "hello",
  print: function () {
    console.log(this.name);
  },
};
obj.print(); // hello

const arrow = () => {
  console.log(this); // 화살표 함수의 this는 상위 스코프의 this
};
arrow();
```

### ✨ 오늘의 느낀점

- 스코프, 클로저, this는 기본 같지만 **면접에서 깊게 물어보면 헷갈릴 수 있는 포인트**가 많음
- 단순히 문법 외우기가 아니라 **언제**, **왜**, **어떤 문제가 생기는지** 위주로 정리하는 게 중요하다고 느낌
- 특히 클로저에서 메모리 누수, this에서 화살표 함수의 동작 이유는 반드시 기억해야겠다.
