## 📆 2025.04.10 (목)

### 🌐 오늘의 주제: 웹소켓 연결이 끊어졌을 때 로직

#### ✅ 웹소켓 기본 구조

웹소켓(WebSocket)은 HTTP 기반이 아닌 **양방향 통신이 가능한 실시간 프로토콜**로,  
클라이언트와 서버 간 지속적인 연결을 유지하여 **실시간 채팅, 알림, 게임, 금융 데이터 전송** 등에 활용된다.

```ts
const socket = new WebSocket("wss://your-server.com/ws");

socket.onopen = () => {
  console.log("connected");
};
socket.onmessage = (event) => {
  handleMessage(event.data);
};
socket.onclose = () => {
  console.log("disconnected");
};
```

#### 🔧 연결 끊김의 주요 원인

- 네트워크 상태 불안정 (모바일 환경에서 자주 발생)
- 사용자가 브라우저 탭을 전환하거나 백그라운드 상태 진입
- 서버 측에서 타임아웃 또는 연결 종료 처리
- 예외: VPN, 프록시 등 외부 환경 간섭

---

#### 🔁 재연결 처리 전략

> 연결이 끊어졌을 때 아무 조치가 없다면 실시간 기능은 무용지물이다.
> 따라서 반드시 “**끊김 감지 → 재연결 시도**” 로직이 필요하다.

##### ✔️ 1. 끊김 감지 (`onclose`)

```ts
socket.onclose = (e) => {
  console.warn("소켓 연결 종료됨. 재연결 시도 중...");
  setTimeout(reconnect, 3000);
};
```

##### ✔️ 2. 재연결 로직

- 일정 시간 간격으로 `WebSocket` 객체 재생성
- 상태 체크 후 연결 성공 시 기존 상태 복원

```ts
function reconnect() {
  socket = new WebSocket(SOCKET_URL);
  initSocketHandlers();
}
```

##### ✔️ 3. 백오프(Backoff) 전략

- 재연결을 너무 자주 시도하면 서버에 부하를 줄 수 있음
- 시도 실패 횟수에 따라 대기 시간을 점점 늘려가는 방식이 바람직

```ts
const delay = Math.min(1000 * 2 ** retryCount, 10000);
setTimeout(reconnect, delay);
```

---

#### 💡 실무 적용 예시

- 실시간 채팅방 기능 구현 중, 서버와 웹소켓 연결이 끊겼을 때 메시지를 못 받는 문제가 있었음
- 사용자에게 “재연결 중입니다…”와 같은 UI를 보여주고, 연결 완료되면 자동으로 이전 대화 내역 fetch
- 연결 실패 횟수도 함께 관리하여, 5번 이상 실패 시 알림창으로 안내

---

#### 🛠️ 테스트하면서 겪은 이슈

- `WebSocket.readyState`가 `CLOSING` 상태일 때 재연결 시도하면 예외 발생 가능
- 연결은 되었지만, `onmessage` 리스너를 다시 설정하지 않아서 메시지를 수신하지 못했던 경험
- 브라우저 탭에서 장시간 대기 → 자동 종료되는데도 `onclose` 이벤트가 발생하지 않는 경우 있음 → ping/pong 전략 고민

---

#### ✍️ 느낀 점

> 실시간 기능을 구현하는 데 있어 “**끊김 복원**”은 필수적인 기능이다.
> 단순히 연결만 되는 것보다, 사용자 입장에서 **끊겼을 때 어떻게 복구되는지가 훨씬 중요한 UX**다.
> 특히 실시간 커머스나 채팅처럼 민감한 서비스에서는 재연결 흐름을 탄탄하게 설계해야 신뢰받을 수 있다는 걸 느꼈다.
> **웹소켓 = 연결보다 유지와 복구가 핵심.**
