## 📆 2025.04.07 (월)

### 🔔 오늘의 주제: FCM(Firebase Cloud Messaging) 알림 푸시에 대해서

#### ✅ 개념 정리

FCM은 Firebase에서 제공하는 무료 알림 전송 플랫폼으로, **앱이나 웹에서 사용자에게 알림을 전달**할 수 있는 서비스다.  
iOS, Android, 웹 등 다양한 플랫폼을 지원하며, **Push Notification**을 비교적 간편하게 구현할 수 있다.

---

#### ⚙️ 웹에서의 FCM 흐름 (PWA 포함)

1. **Firebase Console에서 프로젝트 생성**
   - 웹 앱 등록, VAPID 키 생성
2. **클라이언트에 SDK 설치**
   - `firebase/app`, `firebase/messaging` 라이브러리 설치
3. **서비스 워커 등록**
   - `firebase-messaging-sw.js` 생성 및 등록
4. **알림 권한 요청 및 토큰 발급**
   - `getToken()` 호출하여 브라우저의 FCM 토큰 획득
5. **서버에 토큰 저장**
   - 사용자별로 해당 토큰을 저장해두고, 서버에서 알림 전송 시 사용

---

#### 💡 코드 스니펫 예시

```ts
import { getMessaging, getToken, onMessage } from "firebase/messaging";

const messaging = getMessaging(firebaseApp);

getToken(messaging, { vapidKey: import.meta.env.VITE_VAPID_KEY }).then(
  (currentToken) => {
    if (currentToken) {
      // 서버로 전송
      sendTokenToServer(currentToken);
    } else {
      console.log("No registration token available.");
    }
  }
);
```

```ts
onMessage(messaging, (payload) => {
  console.log("Foreground message received:", payload);
  // 사용자에게 보여줄 알림 처리
});
```

---

#### 🛠️ 트러블슈팅 경험

- `firebase-messaging-sw.js`가 **public 루트에 없으면 브라우저에서 알림 수신이 되지 않음**
- 사용자 브라우저에서 권한을 `거부`하면 다시 요청할 수 없음 → UX 전략 필요
- 토큰이 만료되거나 변경되면 서버에 **재전송 로직** 필요 (앱 진입 시마다 `getToken()` 호출해 비교)

---

#### 📋 고려한 구조

- 회원가입 시 알림 권한은 **요청만** → 수락하지 않아도 정상 가입 가능
- 로그인 시 `getToken()`으로 토큰 발급 → 서버 저장
- 다음 로그인 시 토큰이 변경되었는지 비교 후, 갱신이 필요한 경우만 API 전송

```ts
if (storedToken !== newToken) {
  updateTokenOnServer(newToken);
}
```

---

#### ✍️ 느낀 점

> FCM은 푸시 시스템의 진입 장벽을 낮춰주지만, **실제로 서비스에 녹이려면 디테일한 고려사항**이 많다.
> 특히 사용자 동의 흐름, 토큰 관리, 서비스 워커 위치 등 **브라우저 특유의 제약**을 명확히 알고 있어야 한다.
> 푸시 알림은 단순한 기능이 아니라 사용자 경험에 깊게 관여하므로, **UX와 기술의 밸런스**를 맞추는 것이 중요하다.
