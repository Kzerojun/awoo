## 📆 2025.04.09 (수)

### ⚠️ 오늘의 주제: PWA 서비스에 FCM 푸시 알림을 넣을 때 주의해야 하는 점

#### ✅ 전반적인 구조 이해

PWA와 FCM을 함께 사용하는 것은 웹앱을 마치 네이티브 앱처럼 만드는 데 큰 도움이 되지만,  
**서비스 워커와 FCM의 연동 구조는 꽤 민감하고 까다롭다.**

- PWA는 브라우저 환경에서의 앱 설치 및 오프라인 지원
- FCM은 Firebase 기반 푸시 알림 플랫폼
- 두 기술이 결합되면 웹 환경에서도 푸시 수신 → 앱 알림처럼 동작 가능

---

#### 🔧 주요 기술 스택

- `firebase/app`, `firebase/messaging` for client
- `firebase-messaging-sw.js` (서비스 워커에서 푸시 수신)
- `next-pwa` (Next.js에서 PWA 기능 자동 구성)

---

#### ⚠️ 꼭 지켜야 할 체크리스트

1. **서비스 워커 파일 위치**

   - 반드시 `/public/firebase-messaging-sw.js`에 위치해야 함
   - 상대 경로 X, 루트에서만 작동함 (브라우저 제한 때문)

2. **알림 권한 흐름**

   - `Notification.permission`을 통해 권한 상태 확인
   - `denied`인 경우에는 재요청 불가 → 유저가 직접 브라우저 설정에서 변경해야 함

3. **`getToken()` 사용 시 주의**
   - 기존 토큰과 비교하여 새 토큰이 다르면 서버에 갱신 요청
   - 토큰은 재생성될 수 있으며, 이를 무시하면 알림이 가지 않음

```ts
const token = await getToken(messaging, { vapidKey: VAPID_KEY });
if (storedToken !== token) {
  updateServerToken(token);
}
```

4. **알림 클릭 이벤트 처리**
   - 서비스 워커 내에서 `notificationclick` 이벤트를 수신해 앱 포커싱 또는 라우팅 처리 필요

```ts
self.addEventListener("notificationclick", (event) => {
  event.notification.close();
  event.waitUntil(clients.openWindow("/"));
});
```

---

#### 🧪 테스트 중 겪은 문제들

- `firebase-messaging-sw.js`가 잘못된 위치에 있으면 알림 수신 자체가 안 됨
- 푸시 메시지 수신은 되는데 UI에 표시되지 않으면, `showNotification`이 빠졌을 가능성 있음
- 토큰 재요청 타이밍을 고려하지 않으면, 이전 토큰으로 알림을 보내는 문제가 발생

---

#### 🧠 전략 정리

| 타이밍         | 작업 내용                                          |
| -------------- | -------------------------------------------------- |
| 회원가입 후    | 권한 요청만 (브라우저에서 거절해도 정상 가입 가능) |
| 로그인 시      | `getToken()` → 토큰 저장 or 갱신 요청              |
| 앱 진입 시마다 | 기존 토큰과 비교 → 다르면 서버 갱신                |
| 로그아웃 시    | 저장된 토큰 초기화 or 무효화                       |

---

#### ✍️ 느낀 점

> FCM과 PWA의 조합은 꽤 파워풀하지만, **실제 적용 시에는 브라우저 제약과 구조 이해가 필수**다.
> 특히 `firebase-messaging-sw.js`의 위치와 권한 요청 흐름은 예민하게 설계되어 있어,
> 작동하지 않을 때 어디서 문제가 생겼는지 파악하는 데 시간이 꽤 걸렸다.
> 앞으로는 푸시 관련 기능을 도입할 때, 항상 **토큰 흐름과 권한 상태를 명확히 설계**한 뒤 시작해야겠다고 다짐했다.
> 이후에 사이드 프로젝트로 FCM을 적용해볼 예정
