## 📆 2025.04.08 (화)

### 🛠️ 오늘의 주제: PWA 서비스 워커에 대해서

#### ✅ 서비스 워커란?

서비스 워커(Service Worker)는 브라우저가 백그라운드에서 실행하는 **독립된 JS 스레드**로,  
네트워크 요청을 가로채거나 캐시를 조작하며, **푸시 알림, 오프라인 지원, 백그라운드 동기화** 같은 기능을 가능하게 한다.

- 메인 스레드(UI)와는 완전히 분리되어 비동기적으로 동작
- 사용자가 페이지를 닫아도 백그라운드에서 계속 실행 가능
- React, Vue 등 프레임워크 상관없이 웹 앱에서 사용할 수 있음

---

#### ⚙️ 서비스 워커 작동 흐름

1. **등록 (register)**

```ts
if ("serviceWorker" in navigator) {
  navigator.serviceWorker
    .register("/firebase-messaging-sw.js")
    .then((reg) => console.log("SW Registered!", reg))
    .catch((err) => console.error("SW registration failed:", err));
}
```

2. **설치 (install 이벤트)**

   - 서비스 워커가 최초 설치되며 캐시 저장 등 초기화 수행

3. **활성화 (activate 이벤트)**

   - 이전 워커를 대체하고 새 워커로 활성화

4. **요청 가로채기 (fetch 이벤트)**

   - 사용자의 fetch 요청을 가로채서 오프라인 캐시 또는 API 데이터로 응답

5. **푸시 알림 수신 (push 이벤트)**
   - 서버로부터 수신한 푸시 메시지를 사용자에게 표시

---

#### 💡 실제 적용 (Next.js + PWA)

- `next-pwa`를 사용하여 PWA 자동 설정 가능
- `firebase-messaging-sw.js`는 반드시 **퍼블릭 루트 폴더**에 위치해야 한다.
- 서비스 워커 내에서는 DOM 접근 불가 (UI 처리 불가능)

---

#### 🧪 테스트하면서 배운 점

- 서비스 워커를 수정할 땐 **브라우저 캐시가 남아있어 바로 반영되지 않음** → DevTools에서 'Update on reload' 옵션 체크 필요
- 설치된 워커가 예상대로 동작하지 않을 경우, `chrome://serviceworker-internals`에서 등록 정보 확인 가능
- fetch 캐시 전략을 잘못 설정하면, 오히려 최신 데이터를 받지 못하는 오류 발생

---

#### 🌐 주요 기능 예시

1. **오프라인 캐싱**

   - 특정 정적 리소스를 설치 시점에 미리 캐시하여, 오프라인 상태에서도 앱 사용 가능

2. **푸시 알림 처리**

   ```js
   self.addEventListener("push", (event) => {
     const data = event.data?.json();
     self.registration.showNotification(data.title, {
       body: data.body,
       icon: "/logo.png",
     });
   });
   ```

3. **백그라운드 데이터 싱크 (지원 브라우저 한정)**

---

#### ✍️ 느낀 점

> 서비스 워커는 웹앱이 네이티브 앱처럼 동작하게 만들어주는 **PWA의 핵심 기술**이다.
> 파일 위치, 등록 방식, 권한 등 기본 설정을 놓치면 전혀 작동하지 않기 때문에 세세한 구조와 흐름을 완전히 이해해야 했다.
> 개념은 어렵지 않지만, **디버깅이 쉽지 않다는 점에서 실무 경험이 많이 필요한 영역**이라고 느꼈다.
