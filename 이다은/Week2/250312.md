# 🖥️ 운영체제 - 프로세스와 쓰레드

## 1. 프로세스(Process)와 쓰레드(Thread)

### 🔹 프로세스(Process)란?

- 프로세스란 **실행 중인 프로그램**을 의미한다.
- 운영체제가 할당하는 실행 단위이며, **CPU, 메모리, 파일, 입출력 장치 등의 자원을 할당받아 실행**된다.
- 하나의 프로세스는 최소 하나 이상의 **쓰레드(Thread)**를 포함한다.
- 프로세스는 **독립적인 실행 환경을 가지며**, 다른 프로세스와 메모리를 공유하지 않는다.

### 🔹 쓰레드(Thread)란?

- 쓰레드는 **프로세스 내에서 실행되는 하나의 흐름**이다.
- 같은 프로세스 내의 여러 쓰레드는 **코드, 데이터, 힙 영역을 공유**하며 실행된다.
- 쓰레드는 각각 독립적인 **레지스터, 스택(Stack) 영역**을 가진다.
- 멀티 쓰레드를 사용하면 **프로세스 내에서 여러 작업을 동시에 수행**할 수 있다.

## 2. 컨텍스트 스위칭(Context Switching)

### 🔹 컨텍스트 스위칭이란?

- 운영체제에서 **CPU가 하나의 프로세스에서 다른 프로세스로 전환될 때 발생하는 과정**이다.
- 프로세스의 실행 상태(Context)를 저장하고, 새로운 프로세스의 상태를 복원하는 과정이 필요하다.

### 🔹 컨텍스트 스위칭이 발생하는 경우

1. **멀티태스킹**: CPU가 여러 프로세스를 빠르게 번갈아가며 실행할 때
2. **인터럽트(Interrupt)**: 입출력(I/O) 작업이 발생하여 CPU가 다른 작업을 수행해야 할 때
3. **프로세스 간 전환**: 한 프로세스가 종료되거나 다른 프로세스가 우선순위가 높을 때

### 🔹 컨텍스트 스위칭의 비용

- **CPU 레지스터 및 프로세스 제어 블록(PCB)을 저장 및 복원해야 하므로 오버헤드 발생**
- 컨텍스트 스위칭이 잦아지면 시스템 성능 저하

## 3. 프로세스 제어 블록(PCB, Process Control Block)

### 🔹 PCB란?

- 운영체제가 **프로세스를 관리하기 위해 정보를 저장하는 데이터 구조**
- 각 프로세스는 고유한 PCB를 가지며, **프로세스 실행 상태를 저장**한다.

### 🔹 PCB의 주요 정보

1. **프로세스 ID (PID)** - 프로세스를 식별하는 고유한 번호
2. **프로세스 상태** - 실행(Running), 대기(Waiting), 준비(Ready) 등의 상태
3. **프로그램 카운터(PC)** - 실행해야 할 다음 명령어의 주소
4. **CPU 레지스터** - 프로세스 실행 중 CPU가 사용하는 레지스터 값
5. **메모리 정보** - 코드, 데이터, 스택, 힙 등의 메모리 정보
6. **입출력 상태 정보** - 할당된 파일, 입출력 장치 상태

## 4. 멀티 쓰레드와 멀티 프로세스

### 🔹 멀티 쓰레드(Multi-thread)

- 하나의 프로세스에서 **여러 개의 쓰레드가 동작**하는 방식
- **장점**
  - 같은 메모리 공간을 공유하여 **문맥 전환(Context Switching) 비용이 적음**
  - 쓰레드 간 **데이터 공유가 용이**
  - **빠른 응답성**, 자원 사용 효율 증가
- **단점**
  - 쓰레드 간 공유 자원을 잘못 관리하면 **동기화 문제(경쟁 조건, 데드락 등)**가 발생할 수 있음

### 🔹 멀티 프로세스(Multi-process)

- 하나의 응용 프로그램을 여러 개의 프로세스로 나누어 실행하는 방식
- **장점**
  - 프로세스 간 메모리를 공유하지 않아 **안정성 높음**
  - 하나의 프로세스가 종료되어도 다른 프로세스에 영향을 주지 않음
- **단점**
  - **컨텍스트 스위칭 비용이 크고**, 프로세스 간 통신(IPC)이 복잡함

## 5. 쓰레드마다 독립적으로 할당하는 2가지

쓰레드는 **공유 자원(코드, 데이터, 힙)**을 사용하는 반면, 다음 두 가지는 독립적으로 할당된다.

1. **스택(Stack)**
   - 함수 호출 시 지역 변수, 매개변수, 리턴 주소를 저장
   - 각 쓰레드는 독립적인 스택을 가지며, 다른 쓰레드와 공유하지 않음
2. **레지스터(Registers)**
   - CPU가 현재 실행 중인 쓰레드의 상태를 저장
   - 쓰레드 간 문맥 전환(Context Switching) 시 레지스터 값도 함께 변경됨

## 6. 멀티 쓰레드 환경에서 주의해야 할 점

멀티 쓰레드 환경에서는 **여러 쓰레드가 동시에 실행**되면서 발생할 수 있는 문제를 방지해야 한다.

1. **경쟁 조건(Race Condition)**

   - 두 개 이상의 쓰레드가 동시에 공유 데이터에 접근하여 의도하지 않은 결과를 초래하는 문제
   - 해결책: **뮤텍스(Mutex), 세마포어(Semaphore) 등 동기화 기법 활용**

2. **데드락(Deadlock)**

   - 여러 쓰레드가 서로의 자원을 기다리며 무한 대기 상태에 빠지는 현상
   - 해결책: **교착 상태 회피 알고리즘 사용 (예: 은행가 알고리즘)**

3. **컨텍스트 스위칭 비용**
   - 쓰레드 간 전환이 자주 발생하면 성능 저하 가능
   - 해결책: **적절한 스케줄링 기법 활용**

## 7. 동기(Synchronous)와 비동기(Asynchronous) 차이

### 🔹 동기(Synchronous)

- 작업을 수행할 때 **순차적으로 실행**되는 방식
- 이전 작업이 끝나야 다음 작업이 실행됨
- 예시: 파일 읽기, 함수 호출

### 🔹 비동기(Asynchronous)

- 작업을 수행할 때 **다른 작업과 동시에 실행**되는 방식
- 실행 완료를 기다리지 않고 다른 작업을 수행할 수 있음
- 예시: AJAX 요청, 이벤트 기반 프로그래밍

| 비교 항목      | 동기(Synchronous)      | 비동기(Asynchronous)         |
| -------------- | ---------------------- | ---------------------------- |
| 실행 방식      | 순차적 실행            | 병렬 실행 가능               |
| 작업 완료 여부 | 이전 작업 완료 후 실행 | 다른 작업과 동시에 실행 가능 |
| 예시           | 파일 읽기, 함수 호출   | 네트워크 요청, 이벤트 리스너 |

## 8. 프로세스의 종류

1. **Foreground Process (전면 프로세스)**

   - 사용자가 직접 실행하고, **UI를 제공하는 프로세스**
   - 예: 웹 브라우저, 게임, 텍스트 에디터

2. **Background Process (백그라운드 프로세스)**

   - UI 없이 **백그라운드에서 실행되는 프로세스**
   - 예: 백업 프로그램, 백그라운드 서비스

3. **Daemon Process (데몬 프로세스)**

   - 시스템이 부팅될 때 자동으로 실행되며, 특정 작업을 수행하는 프로세스
   - 예: 웹 서버, 데이터베이스 서버

4. **Zombie Process (좀비 프로세스)**
   - 종료되었지만 부모 프로세스가 아직 수거하지 않은 프로세스
   - `ps` 명령어에서 `<defunct>`로 표시됨

## 🔚 결론

- 프로세스와 쓰레드는 운영체제에서 중요한 개념이며, 각각의 특징을 이해하고 활용해야 한다.
- 멀티 쓰레드는 성능 향상을 제공하지만, 동기화 문제를 주의해야 한다.
- 동기와 비동기의 차이를 이해하면 효율적인 프로그램을 설계할 수 있다.
