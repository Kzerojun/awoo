# 📌 250311 - 운영체제(OS) 개념 정리

## 1. 운영체제(OS)란?

운영체제(Operating System, OS)는 컴퓨터 시스템의 하드웨어를 관리하고, 응용 프로그램과 하드웨어 사이의 중재자 역할을 하는 소프트웨어이다.  
즉, **사용자와 하드웨어 간의 인터페이스 역할**을 수행하며, 컴퓨터가 원활하게 작동할 수 있도록 여러 가지 기능을 제공한다.

### 운영체제의 주요 기능

- **프로세스 관리(Process Management)**
  - 여러 개의 프로그램(프로세스)을 동시에 실행하는 환경을 제공하며, CPU 스케줄링을 통해 효율적으로 자원을 분배한다.
- **메모리 관리(Memory Management)**

  - 실행 중인 프로그램이 필요한 만큼의 메모리를 할당하고, 사용이 끝나면 해제하는 역할을 한다.

- **파일 시스템 관리(File System Management)**

  - 데이터를 저장하고 관리할 수 있도록 파일 및 디렉터리 구조를 제공한다.

- **입출력 장치 관리(I/O Management)**

  - 키보드, 마우스, 디스크, 네트워크 등의 입출력 장치를 효율적으로 제어한다.

- **사용자 인터페이스 제공(User Interface)**
  - CLI(Command Line Interface) 또는 GUI(Graphical User Interface)를 통해 사용자와 상호작용할 수 있도록 지원한다.

---

## 2. 인터페이스(Interface)란?

**인터페이스**란 서로 다른 두 시스템(소프트웨어와 하드웨어, 하드웨어 간, 소프트웨어 간)이 정보를 주고받는 접점(경계)을 의미한다.

### 운영체제에서의 인터페이스 예시

- **하드웨어와 소프트웨어 사이**

  - 운영체제는 응용 프로그램이 하드웨어를 직접 제어하지 않도록 인터페이스 역할을 하며, 응용 프로그램이 OS를 통해 하드웨어에 접근할 수 있도록 한다.

- **사용자와 운영체제 사이**
  - 운영체제는 사용자가 컴퓨터를 쉽게 사용할 수 있도록 **CLI(명령줄 인터페이스)**나 **GUI(그래픽 사용자 인터페이스)**를 제공한다.
  - CLI: 명령어를 입력해 컴퓨터와 상호작용 (예: 터미널, 명령 프롬프트)
  - GUI: 그래픽 환경에서 마우스 클릭과 같은 직관적인 방식으로 상호작용 (예: Windows, macOS의 UI)

---

## 3. 커널(Kernel)이란?

운영체제는 하나의 프로그램으로 볼 수 있지만, 크기가 매우 크기 때문에 모든 운영체제 기능을 한꺼번에 메모리에 올리는 것은 비효율적이다.  
이 문제를 해결하기 위해, **운영체제의 핵심 부분만을 메모리에 상주시켜 관리하는 구조**를 채택하는데, 이 핵심 부분을 **커널(Kernel)**이라고 한다.

### 커널의 역할

- **프로세스 관리**
  - 여러 개의 프로그램(프로세스)이 CPU를 사용할 수 있도록 스케줄링하고 실행 상태를 관리한다.
- **메모리 관리**

  - 현재 실행 중인 프로그램이 필요한 만큼의 메모리를 할당하고, 불필요한 메모리는 해제한다.

- **파일 시스템 관리**

  - 데이터를 저장하는 파일 및 디렉터리 시스템을 관리한다.

- **장치 드라이버 관리**
  - 키보드, 마우스, 디스크, 네트워크 카드 등 다양한 하드웨어 장치를 제어하고 관리한다.

### 커널의 종류

1. **모놀리식 커널(Monolithic Kernel)**

   - 운영체제의 모든 기능이 하나의 커널 공간에서 실행됨. (예: Linux)

2. **마이크로커널(Microkernel)**
   - 커널의 크기를 최소화하고, 프로세스 간 통신(IPC)과 기본적인 기능만 담당하며, 나머지는 사용자 모드에서 수행. (예: MacOS X, QNX)

---

## 4. 메모리 구조의 영역별 설명

컴퓨터에서 프로그램이 실행될 때 메모리는 특정한 영역으로 나뉘어 관리된다.

### 1️⃣ 코드(Code) 영역

- 실행할 프로그램의 **코드(명령어)**가 저장되는 영역이다.
- 프로그램이 실행될 때 읽기 전용(Read-only)으로 사용된다.
- 컴파일된 바이너리 코드가 저장되며, 일반적으로 **CPU가 실행할 명령어**를 포함한다.

### 2️⃣ 데이터(Data) 영역

- 프로그램이 사용하는 **전역 변수(global variable), 정적 변수(static variable)**가 저장되는 공간이다.
- 프로그램 실행 동안 메모리에 유지되며, 프로그램이 종료될 때까지 사라지지 않는다.

### 3️⃣ 힙(Heap) 영역

- 실행 중 **동적으로 할당되는 메모리**가 저장되는 영역이다.
- `malloc()`, `new` 같은 메모리 동적 할당 함수에 의해 공간이 할당되며, 수동으로 해제해야 한다(`free()`, `delete`).
- **메모리 누수(Memory Leak)**가 발생할 위험이 있음.

### 4️⃣ 스택(Stack) 영역

- 함수 호출 시 **지역 변수, 매개변수, 리턴 주소** 등을 저장하는 영역이다.
- **LIFO(Last In First Out)** 구조로 동작하며, 함수가 끝나면 자동으로 해제된다.
- 크기가 제한적이며, 너무 많은 재귀 호출 시 **스택 오버플로우(Stack Overflow)**가 발생할 수 있다.

---

## 5. 힙(Heap)과 스택(Stack) 차이점 비교

| 구분                 | 힙(Heap)                           | 스택(Stack)                 |
| -------------------- | ---------------------------------- | --------------------------- |
| **저장 데이터**      | 동적 할당된 객체, 배열 등          | 함수의 지역 변수, 매개변수  |
| **할당 시점**        | 실행 중(runtime)                   | 함수 호출 시(compile-time)  |
| **메모리 할당 방식** | 명시적으로 `malloc()`/`new`로 할당 | 자동 할당 및 해제           |
| **해제 방식**        | `free()`/`delete`로 수동 해제      | 함수 종료 시 자동 해제      |
| **메모리 크기**      | 상대적으로 큼                      | 제한적                      |
| **성능**             | 속도가 느림(할당/해제 비용 높음)   | 속도가 빠름(자동 할당/해제) |

### 📌 힙 영역과 스택 영역의 차이점 정리

- **힙(Heap)**

  - 실행 중 **동적으로 메모리를 할당**할 때 사용된다.
  - 사용자가 직접 해제(`free()`, `delete`)해야 하며, 이를 잊을 경우 **메모리 누수**가 발생할 수 있다.
  - 크기가 크지만 속도가 상대적으로 느리다.

- **스택(Stack)**
  - 함수 호출 시 자동으로 할당되며, 함수가 끝나면 자동 해제된다.
  - 속도가 빠르지만 크기가 제한적이며, 너무 많은 재귀 호출이 발생하면 **스택 오버플로우**가 발생할 수 있다.

---

## 📝 정리

- **운영체제(OS)** 는 하드웨어를 관리하고 응용 프로그램과 사용자 간의 인터페이스 역할을 수행한다.

- **커널(Kernel)** 은 운영체제의 핵심 기능을 담당하는 부분으로, 메모리에 상주하여 CPU, 메모리, 파일 시스템 등을 관리한다.

- **메모리 구조** 는 코드 영역, 데이터 영역, 힙 영역, 스택 영역으로 나뉘며, 각각의 역할이 다르다.

- **힙(Heap)과 스택(Stack)의 차이** 는 메모리 할당 방식, 크기, 속도 측면에서 큰 차이를 가진다.
