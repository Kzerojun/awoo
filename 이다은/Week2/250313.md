### ⚡ Blocking과 Non-Blocking

🔹 **Blocking**: 특정 작업이 완료될 때까지 프로세스가 대기하는 방식.

- ⏳ 예: 동기 I/O → 파일을 읽을 때 완료될 때까지 다른 작업 불가.  
  🔹 **Non-Blocking**: 특정 작업을 요청한 후 결과를 기다리지 않고 다른 작업을 수행할 수 있는 방식.
- 🚀 예: 비동기 I/O → 파일을 읽는 동안 다른 작업 수행 가능.

### 🖥️ 프로세스의 종류

1. **Foreground Process (전경 프로세스)** 🏃‍♂️
   - 사용자와 직접 상호작용하는 프로세스 (ex. 터미널 명령어 실행)
2. **Background Process (백그라운드 프로세스)** 🌙
   - 백그라운드에서 실행되는 프로세스 (ex. 데몬, 크론 작업)
3. **Zombie Process (좀비 프로세스)** 🧟
   - 부모 프로세스가 종료되지 않고 자식 프로세스의 종료를 확인하지 않으면 발생.
4. **Orphan Process (고아 프로세스)** 🍼
   - 부모 프로세스가 먼저 종료되어 `init` 프로세스가 관리하게 됨.

### 🔥 DeadLock (교착 상태)란?

- 두 개 이상의 프로세스가 서로 자원을 점유한 채 상대방의 자원을 기다리며 멈춰있는 상태.
- 🚨 교착 상태 발생 조건 (4가지):
  1. **상호 배제 (Mutual Exclusion)**: 한 번에 하나의 프로세스만 자원을 사용할 수 있음.
  2. **점유 및 대기 (Hold and Wait)**: 하나의 프로세스가 자원을 점유한 채 추가 자원을 요청하며 대기.
  3. **비선점 (No Preemption)**: 자원을 강제로 빼앗을 수 없음.
  4. **순환 대기 (Circular Wait)**: 프로세스들이 서로 자원을 대기하며 순환 구조를 형성.
- ✅ 해결 방법: 예방, 회피, 탐지 및 복구

## 🐳 도커(Docker)란?

💡 컨테이너 기반의 가상화 기술로, 애플리케이션과 실행 환경을 함께 패키징하여 어디서든 동일한 환경에서 실행 가능하게 함.

### 🏗️ Docker의 핵심 개념

🔹 **이미지 (Image)**: 실행 가능한 애플리케이션 및 종속성을 포함한 파일 시스템 스냅샷.  
🔹 **컨테이너 (Container)**: 이미지를 실행한 인스턴스로, 격리된 환경에서 실행됨.  
🔹 **도커 허브 (Docker Hub)**: 공개 및 개인 도커 이미지를 공유할 수 있는 레지스트리.  
🔹 **도커 컴포즈 (Docker Compose)**: 여러 컨테이너를 정의하고 관리하는 도구.

### 🎯 배포 환경 기본 이해

1. **개발 환경 (Development)** 💻
   - 로컬에서 개발 및 테스트를 수행하는 환경.
2. **테스트 환경 (Staging / QA)** 🔍
   - 실제 운영 환경과 유사하게 테스트를 진행하는 환경.
3. **운영 환경 (Production)** 🚀
   - 실제 사용자들에게 제공되는 환경.
4. **CI/CD (Continuous Integration / Continuous Deployment)** ⚙️
   - 지속적인 통합 및 배포를 자동화하여 빠른 배포와 오류 최소화 가능.
