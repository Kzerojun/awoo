# FCM 기본 개념

- Firebase Cloud Messaging: Firebase에서 제공하는 무료 Push Notification 서비스
- 클라이언트 (웹, 앱)와 서버 간의 실시간 알림을 위함.
- 브라우저 푸시로 연결 시 Web Push Protocol을 사용
- Android, iOS, Web 모두 지원

## 동작 흐름

```
Firebase → 사용자 브라우저
└> FCM SDK 등록 (service worker)
└> 사용자 권한 획득
└> FCM 토큰 발급
└> 발급된 토큰을 서버로 전송
└> 서버가 FCM으로 푸시 발송
└> 클라이언트는 service worker에서 수신
```

## 어제 실제로 설정한 작업 내용

1. Firebase 프로젝트 설정 (백엔드)

   - Firebase 콘솔에서 프로젝트 생성
   - Web 앱 등록 후 발급받은 firebaseConfig 등을 전달 받음

2. firebase-messaging-sw.js 파일 작성

   - public 폴더에 service worker 등록
   - 알림 수신 로직 작성

3. FCM 초기화 및 토큰 발급

   - Firebase SDK 설치 후 getToken() 으로 사용자 브라우저에서 FCM 토큰 발급
   - 현재는 전역에 설정, 서비스 URL로 진입 시 바로 알림 수신 가능
   - 테스트 후 로그인 직후 발급 / 로그아웃 후 리셋 예정
   - 발급된 토큰을 서버로 전송 (서버가 이 토큰으로 FCM 푸시)

4. Notification Permission

   - 브라우저 알림 권한 요청
   - 거부하면 푸시 불가
   - 나는 회원가입 단계에서 알림 수신 동의도 포함시키는 걸 추천

5. 알림 수신 테스트
   - Postman 또는 Firebase Console에서 알림 테스트 예정

## 헷갈렸던 부분 & 해결 방법

| 헷갈렸던 부분                 | 해결 방법                                                 |
| ----------------------------- | --------------------------------------------------------- |
| service worker 등록 위치      | 반드시 public/ 폴더 최상단에 있어야 정상 동작 (Next.js)   |
| 토큰이 안 나오는 문제         | 알림 권한을 허용해야 getToken()이 토큰 반환               |
| 서버에 토큰 전송 시기         | 토큰 발급 직후 전송해야함 (useEffect + async 함수로 처리) |
| service worker 내 import 문제 | importScripts 로 firebase SDK를 불러야 함                 |

## 핵심 코드 정리

```ts
// firebase.js
import { initializeApp } from "firebase/app";
import { getMessaging, getToken, onMessage } from "firebase/messaging";

const firebaseConfig = {
  // 발급 받은 config
};

const app = initializeApp(firebaseConfig);
const messaging = getMessaging(app);

export const requestPermission = async () => {
  const permission = await Notification.requestPermission();
  if (permission === "granted") {
    const token = await getToken(messaging, {
      vapidKey: "YOUR_PUBLIC_VAPID_KEY",
    });
    console.log("FCM Token:", token);
    // 서버로 전송 로직
  }
};

onMessage(messaging, (payload) => {
  console.log("Foreground Message:", payload);
});
```

## 메모

- 알림 권한 먼저 받고, 토큰 받아야 정상 동작
- service worker는 public에 있어야 한다 (Next.js는 /public/)
- onMessage()는 탭이 열려있을 때만 동작, 꺼진 상태는 service worker가 담당
- 토큰 갱신, 재발급 처리도 나중에 꼭 해줘야 함

## FCM 토큰 주요 재발급 케이스

| 케이스                         | 설명                                             |
| ------------------------------ | ------------------------------------------------ |
| 사용자 앱 데이터를 삭제한 경우 | 브라우저 캐시, 스토리지 삭제 또는 앱 삭제/재설치 |
| 알림 권한 제거 후 재허용       | Notification permission 변경                     |
| 브라우저나 FCM SDK 업데이트    | 환경 변화                                        |
| 토큰 만료                      | 자동으로 새 토큰 발급                            |
| 수동으로 getToken() 호출       | 새 토큰 반환 가능                                |

## 결론

1. 회원가입 시 최초 알림 권한 설정
2. 앱 최초 진입 또는 로그인 시  
   → getToken()으로 토큰 획득 후 서버로 전송
3. 매번 앱 진입 시  
   → 기존 토큰과 새로운 토큰이 다르면 서버에 갱신
4. 알림 권한 변경 시  
   → 브라우저 이벤트로 권한 변경 감지 후 재요청
