# 📚 CSR vs SSR

## 🚀 CSR (Client Side Rendering, 클라이언트 사이드 렌더링)

모든 렌더링이 브라우저(클라이언트)에서 일어나는 방식

- SPA(Single Page Application)의 기본 구조
- 최초에는 `HTML + JS` 만 받아옴
- 브라우저가 JS를 실행하면서 → API 요청 → 렌더링  
  👉 React, Vue 등 대부분 프론트 프레임워크의 기본

```
[브라우저 요청] → [HTML + JS 받음] → [API 호출] → [화면 렌더링]
```

### ✨ 장점

- 로딩 이후 인터랙션 속도가 빠름 (비동기 중심)
- 서버 부하가 적음

### ⚠️ 단점

- 최초 로딩 속도 느림 (API 로딩까지 기다림)
- SEO(검색엔진 최적화)에 불리함 (검색 엔진이 JS 실행 어려움)

---

## 🖥️ SSR (Server Side Rendering, 서버 사이드 렌더링)

서버에서 미리 HTML을 만들어서 클라이언트로 넘겨주는 방식

- Next.js 같은 프레임워크에서 많이 씀
- 서버가 API 요청 → HTML 생성 → 사용자에게 전달

```
[브라우저 요청] → [서버에서 HTML 완성] → [렌더링]
```

### ✨ 장점

- 초기 로딩 빠름 (이미 완성된 HTML)
- SEO에 유리 (검색엔진이 바로 읽을 수 있음)

### ⚠️ 단점

- 서버 부하 큼
- 사용자 인터랙션 이후에는 결국 CSR처럼 동작 (Hydration 필요)
- 실시간 인터랙션은 CSR 만큼 부드럽지 않음

---

## 🆚 CSR vs SSR 비교

| 구분                         | CSR           | SSR            |
| ---------------------------- | ------------- | -------------- |
| ⏱️ 초기 로딩                 | 느릴 수 있음  | 빠름           |
| 🔍 SEO                       | 약함          | 강함           |
| 💾 서버 부하                 | 적음          | 큼             |
| 🖱️ 클라이언트에서의 부드러움 | 매우 부드러움 | Hydration 필요 |

---

## 🔄 여기서 persist와 연관성

- persist를 redux에 도입하는 과정에서 생성형 AI가 위험을 경고하여 더 찾아보게 되었음.
- `persist(localStorage, sessionStorage, 쿠키)`로 클라이언트가 새로고침해도 데이터를 유지하는 기능은 CSR 환경에서만 100% 동작하는 것처럼 보이지만, 실제로는 SSR+CSR (Next.js) 구조에서도 사용 가능함.
- 다만 서버에서는 로컬 스토리지를 읽을 수 없어서 CSR 단계로 넘어간 뒤에 persist 처리가 적용됨.
- 그래서 persist 할 때 **window 객체 체크** 잘 해야 한다!
- 서버에선 window 없음 → CSR만 존재 라는 흐름 때문임.

## 왜 persist 할 때 window 객체 체크를 해야할까?

### ✅ 이유

window 객체는 오직 브라우저 안에만 존재한다.
근데, SSR은 서버에서도 자바 스크립트 코드를 실행함.
서버는 브라우저가 아니니까 window 자체가 없어.

### 예를들어

```
const data = window.localStorage.getItem('my-data');
```

이 코드를 그냥 SSR 환경에서 실행하면?  
| 서버 : "응? window가 뭔데? 그런거 없음" -> 바로 에러 뜸 (ReferenceError: window is not defined)

### 그래서 해결방법

```
if (typeof window !== 'undefined') {
   // 브라우저에서만 실행됨
   const data = window.localStorage.getItem('my-data');
}
```

이렇게 체크하면

- 서버에서는 이 코드를 스킵하고
- CSR (브라우저)에서는 정상 실행함

## 🟣 쉽게 말하면

- CSR은 브라우저 안에서 돌아서 persist(storage) 잘 먹힘
- SSR은 서버에서 처음 돌지만, hydrate 이후 CSR로 넘어가야 persist 됨
- 그래서 Next.js 같은 SSR 프레임워크에서도 persist 잘 쓰긴 함  
  ➤ 다만 CSR 이후에만 정상 작동  
  ➤ `typeof window !== 'undefined'` 체크 자주 등장

---

## ✅ 정리

- CSR: SPA에서 persist, localStorage, sessionStorage 자유롭게 쓴다.
- SSR: 서버에서는 persist 바로 못 쓰고, CSR로 넘어간 뒤에 써야 함.
