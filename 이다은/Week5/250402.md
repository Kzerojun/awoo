# 🌐 SPA (Single Page Application)

### ✅ 정의

> 한 번 페이지를 로딩한 뒤, 필요한 데이터만 바꿔가며 사용하는 웹 애플리케이션 구조

- **전통적인 웹사이트(MPA)**: 요청할 때마다 HTML 전체 다시 받아옴
- **SPA**: 최초 1번만 HTML 로딩 → 이후엔 JS가 화면만 바꿔줌

### ✅ 특징

- 페이지 이동 시 전체 새로고침 ❌, 라우팅은 JS가 담당 (React Router, Vue Router 등)
- 화면 일부만 바뀌므로 **부드러운 UX** 제공
- 데이터만 주고받는 구조 → **API 중심 백엔드**와 잘 어울림

### ✅ 장단점

| 장점                | 단점                     |
| ------------------- | ------------------------ |
| 빠른 페이지 전환    | SEO에 약함               |
| 부드러운 UX         | 초기 로딩이 느릴 수 있음 |
| 프론트-백 분리 쉬움 | 복잡한 상태 관리 필요    |

# 📡 WebSocket + STOMP

### ✅ WebSocket이란?

> HTTP와 달리 **양방향 통신**이 가능한 실시간 연결 방식

- 기본은 TCP 기반
- 서버와 클라이언트가 계속 연결된 상태로 데이터를 주고받음
- 주로 채팅, 알림, 주식/코인 실시간 데이터 등에 사용

```plaintext
HTTP: 요청 → 응답 (단방향)
WebSocket: 연결 유지 → 언제든지 서버와 주고받기 (양방향)
```

---

### ✅ STOMP란?

> WebSocket 위에서 사용하는 **메시징 프로토콜**  
> (📬 WebSocket의 "편지봉투" 역할)

- **Simple Text Oriented Messaging Protocol**
- publish/subscribe 개념으로 메시지 주고받음
- 채팅방, 실시간 알림에서 **주제(topic)를 구독하고**, **메시지를 발행(publish)** 함

### 🔧 구조 예시

- 클라이언트가 `/sub/chat/room/123` 구독 (subscribe)
- 서버는 메시지를 `/pub/chat/room/123`으로 받음 (publish)
- 서버가 다시 브로드캐스트 → 구독자들에게 실시간 전달

```js
stompClient.subscribe("/sub/chat/room/123", onMessage);
stompClient.send("/pub/chat/room/123", {}, JSON.stringify(msg));
```

## 🔄 SPA와 WebSocket은 어떻게 연결될까?

SPA는 전체 새로고침 없이 데이터만 바꾸니까  
📡 **실시간성**이 중요한 서비스와 찰떡임!

### 예시

- React/Vue SPA에서
  - WebSocket으로 실시간 채팅방
  - 실시간 알림, 실시간 주가 반영 등 구현 가능
- 새로고침 없이 화면이 바뀌므로 WebSocket 연결도 유지됨

야 이거 진짜 좋은 질문이다.  
지금 상황이면 **STOMP** 쓸지, 그냥 **WebSocket**만 쓸지, 혹은 다른 프로토콜을 쓸지 고민하는 타이밍 맞음.

---

## 💡 WebSocket에서 사용할 수 있는 프로토콜 종류

| 종류               | 특징                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| **Pure WebSocket** | 가장 기본적인 소켓 (프레임워크 없음)                                 |
| **STOMP**          | 텍스트 기반 Pub/Sub 메시징 프로토콜 (Spring, SockJS, 채팅에 많이 씀) |
| **Socket.IO**      | WebSocket + fallback + custom 프로토콜 (Node.js 진영에서 많이 씀)    |
| **MQTT**           | IoT, 모바일 장비에서 많이 씀 (경량, 저전력)                          |

## ✅ 우리 프로젝트 상황 분석

> 중고거래 서비스
>
> - 사용자 간 **1:1 채팅**
> - 거래 채팅 중 실시간으로 송금/알림도 표시
> - 유저가 채팅방에 입장하고 나가고, 메세지를 주고받음
> - 백엔드는 **Spring 기반** + **SockJS** 사용

## ✔️ **STOMP를 쓰면 좋은 이유**

### 1. **Pub/Sub 구조에 딱 맞음**

- 채팅방 = 구독(Subscribe)할 주제(topic)
- 채팅 보내기 = 발행(Publish)
- 채팅방 참여자끼리만 브로드캐스팅됨
  → 채팅방 구조 만들기 아주 쉬움

---

### 2. **Spring, SockJS와 궁합 최고**

- Spring에서는 `spring-websocket` + `spring-stomp`로 이미 검증된 구조
- SockJS로 fallback 처리 가능 (웹소켓 연결 안 될 때 long-polling 지원)
- 실시간 사용자 수, 접속 상태, 입장/퇴장 메시지 전송까지 패턴화 되어 있음

---

### 3. **메시지 구조가 깔끔**

- STOMP는 메시지에 command + header + body를 붙여서 전송
- header에 유저정보, 채팅방ID, 메시지타입 이런거 넣기 딱 좋음
- 금융 서비스처럼 메시지 신뢰성이 중요한 곳에 유리함

---

### 4. **1:N 구조도 확장 쉬움**

- 나중에 단순 채팅 말고
  - 거래 알림
  - 송금 완료 알림
  - 송금 도중 오류 알림  
     같은 것도 실시간으로 뿌릴 수 있음  
    → STOMP Topic을 늘리면 쉽게 커버 가능
